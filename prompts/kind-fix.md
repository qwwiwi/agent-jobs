## Checklist (kind: fix)

- First reproduce the problem with a failing test.
- Then make the minimal change, run the tests, and create a local commit.
- In Evidence, name each new test and how it failed before your change and passes after.
- Do not make up a fact you do not have (a URL, a price, a name, a version, an API field, a config value). Write a visible placeholder instead, `<<PLACEHOLDER: what is missing>>`, and list each one in Not done / uncertain.
- When the job covers requirements, end each commit message with a trailer naming the ones it touches: `Requirements: R01, R03i`.
- A part the brief does not allow (outside its scope, needs access you lack, breaks a rule) is not done. Write one line for it in Not done / uncertain: `BLOCKED: <requirement or item> · <why>`. A covered requirement you blocked is `missing` or `partial` in the `### Requirements` block.
- UI changes: when your diff touches UI (css/scss, html, jsx/tsx, vue/svelte, templates, static-site renderers, design tokens), before you report done load every changed page in a real headless browser. The default tool is `node <job dir>/tools/ui-check.mjs <base-url> <path>... --out <job dir>/ui-check` (Playwright from your environment; serve the site locally first); the repo's own e2e tool is fine if it covers the same. Device matrix at least 360x740, 390x844, 768x1024, 1366x768, 1920x1080; light and dark scheme when the site has both. Check the full page length (scroll to the end so lazy content loads), not just the first screen: no horizontal page scroll (`documentElement.scrollWidth <= clientWidth`), no visible element sticking out of the viewport outside a scroll container, no broken images, CLS < 0.1, no word split inside a word (e.g. a table cell narrower than its longest word), no 4xx/5xx responses. Save the screenshots in the job dir and list every device x scheme x page with pass/fail in Evidence. If you cannot start a browser (no sockets, no child processes, e.g. the Codex sandbox, or missing system libraries; ui-check.mjs exits 2), «Not done / uncertain» MUST start with `BROWSER CHECK NOT RUN: <reason>`; never claim the UI is verified.
