# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- Job folder size (#43): when an attempt ends, the job folder is measured (the worktree of a repo job left out, symlinks not followed) and stored on the job row and the stats row (columns `jobs.dir_bytes`, `job_stats.dir_bytes`); `job_result` returns `job_dir_bytes`, the job-done line ends with `· job dir <size>` from config `job_dir_note_mb` on (default 100, `0` never), and `system_doctor` lists the five largest job folders with their temp-dir share (`disk.largest_job_dirs`) and the total of all job temp dirs (`disk.job_tmp_bytes`).

### Fixed
- A job's temp files no longer land in the daemon's temp dir (#43): `prepare` creates `<jobdir>/tmp` (0700) and claude (or codex) runs with `TMPDIR`, `GOTMPDIR`, `TMP` and `TEMP` set to it (one helper, `TempEnv`, shared with the acceptance command, which now gets all four for its own `tmp/`). What a killed job leaves there (`go-build*` work dirs of an interrupted `go test`) is removed by the existing 48-hour prune with the rest of the folder. A symlink in place of `tmp/` is refused.
- A wrapper that dies alone (OOM, a crash, a stray kill) no longer leaves claude running after its row turned terminal (#42): the daemon records whether a job's process group is the one it spawned (new column `jobs.pgid_spawned`; a group adopted from the job-writable `wrapper.json` is never marked). When the wrapper died without `exit_code`, the next tick ends that group (SIGTERM, grace, SIGKILL) and the job's acceptance command before the row turns `failed`, and the error says `leftover process group N killed` (or that it survived SIGKILL); the timeout and cancel/stop kill do the same once the wrapper pid is gone. While that group is alive, on every platform, `job_resume` is refused and cleanup and prune leave the job's worktree and folder alone.

## [0.4.0] - 2026-10-18

### Added

Inside a job it runs only with `--inside-job` (test-hooks build). Isolation: inherited `GIT_*` repository overrides are dropped before the first git command, and HOME, `AGENT_JOBS_*`, `XDG_*_HOME` and `CLAUDE_CONFIG_DIR` are the sandbox's before any clone code is built or run (the installer gets an explicit `--skills-dir`; with `--real-model` only the daemon gets the caller's HOME and `CLAUDE_CONFIG_DIR`, and that claude's session data lands there); steps, the daemon and each teardown command run under a supervisor that leads a process group of its own: the script only writes `stop` to its FIFO and waits for it, the supervisor signals only its own group (`kill 0`), so no PID or group id is signalled after it could be reused; the teardown (active step, then the sandbox's queued/running jobs, each `list`/`cancel` with a 10 s deadline, a stuck one failing the run, then the daemon) is idempotent, bounded and survives repeated signals; the installed binary must equal the build and runs the later steps; curl and the real-model marker are required. Tests: `acceptance_clean_clone_test.go`, `acceptance_fake_repo_test.go` (a fake repository: sentinel Git/XDG/Claude/agent-jobs settings, installed bytes, interruption also before a supervisor started, hanging teardown commands, a failing HTTP check; every run under a child-subreaper helper that ends only its own orphans and reports them). README «Release checklist».
- Config `max_running` (integer, 1..8, default 2 when absent): how many jobs of the agent run at once; the rest stay queued. A value outside 1..8 is a config error at load time, never clamped. The effective value shows in `system_doctor` (`queue.max_running`), `agent-jobs status` (no id, `queue:` line) and `GET /v1/health` (`max_running`).
- Heartbeat (Wave D, DEVIATIONS #1), off by default: config `heartbeat` (`enabled` false, `interval_minutes` 60, `night_start_hour` 0 / `night_end_hour` 8, `daily_max_wakes` 6, `goals_file` default `<state>/goals.md`, `model` `sonnet`, `max_budget_usd` 0.2, `timeout_seconds` 60). Every daemon tick a Go gate (goals file present, not night, interval since the last wake and the last decision, daily wake cap, no decision running, no job-done line, missed-check alert or `notify_owner` delivery pending; the daemon's last reason is stored); then one decision call in the background: `claude -p` without tools or MCP servers, one turn, in `<state>/heartbeat` with the jobs' scrubbed environment and containment, with the goals (≤ 8 KB, redacted), the time, the last wake and a state summary; the answer must be exactly `{"wake": bool, "reason": "<= 200 chars"}`, anything else is an error (no wake). The whole heartbeat (gate, claim, decision, delivery) runs under `<state>/heartbeat.lock`, taken before the gate with a fresh time; the claim re-checks the interval and the daily wake cap in its own transaction. A wake answer takes `tmux.lock` and re-checks the delivery under it, right before typing (heartbeat on, not night, nothing pending for the session): if closed, the wake is stored as `suppressed` with the reason; it counts toward the decision interval (the model was called) but not toward the daily wake cap. A wake is delivered only after its row moved from `pending` to `wake` in the store (an abandoned claim or a failed write delivers nothing; run-now reports it) and types only the fixed line `[jobs:heartbeat] wake <id>` through the job-done tmux path: the model's reason never reaches the session as input; it is stored and read with `agent-jobs heartbeat show <id> [--json]` or the orchestrator-only MCP tool `heartbeat_get(id)` as `untrusted_model_reason` (also in `system_doctor`), untrusted model text, not instructions. The decision call's output is capped at 256 KB through the pipes (the cap is a plain `Write`, the pipe keeps draining). New tables `heartbeats` (claimed before the call: a restart never repeats a decision; stale claims become `abandoned`; delivered or the error) and `heartbeat_gate` (additive). `agent-jobs heartbeat run-now --agent A [--dry-run]` (the interval is skipped; dry run: gate and prompt, no model call). `agent-jobs status`, `system_doctor` (`heartbeat`; an undelivered wake is a problem) and `/v1/health` (`heartbeat`, without goals or reason) show it.
- `acceptance_cmd` (Wave D autopilot): `job_start` / `schedule_add` field and `agent-jobs start --acceptance-cmd`, a one-line shell command (≤ 1 KB, no newline/CR/NUL anywhere in the input, also not at either end) a fix or general job must pass; refused for review and research jobs, and refused unless config `acceptance_allowed: true` (default off; the wrapper reloads the config and does not run it when it is off). After claude exits 0 with a report and a complete session sweep, the wrapper runs it with `/bin/sh -c` in the job worktree, inside the job's scope or session, in its own process group (recorded in the row; the daemon's timeout, cancel and stop end it too, also once its leader has exited: then the surviving members of the group are ended through pidfds only when every one carries the job's marker, never a group with a member without it; and the wrapper ends it on SIGTERM/SIGINT/SIGHUP), with a scrubbed environment (`PATH USER LOGNAME SHELL LANG LC_* TZ TERM`, `HOME`/`TMPDIR` a fresh throwaway dir `<jobdir>/acceptance-home`, the job's git environment and job marker) and without the guard; timeout config `acceptance_timeout_minutes` (default 15, max 60). The wrapper records the start and the daemon's deadline for it in one conditional update; the daemon times a job out only through a conditional claim (`timed_out_at`) against the row as it is then, so an acceptance start that races the timeout check is never killed on the old deadline, and the daemon uses the recorded deadline, not its own config. Output tail (64 KB) in `<jobdir>/acceptance.log` (a line cut by the 64 KB cap is dropped whole; the file itself stays raw, like `stderr.log`); `job_result` reads it like `report.md` (state-relative `openat`, no symlinks at any level, one link, own user, at most 65 KB read) and redacts it like `report.md`: a line cut by the read cap is dropped whole, the text is redacted before it is cut to the 16 KB `log_tail` (whose incomplete first line is dropped too). Exit 0 keeps the verdict; non-zero, a timeout or no recorded result fails the job: `acceptance failed (exit N)` / `(timeout after Ns)` / `acceptance did not run`, the job-done line ends `· acceptance failed (exit N)` (or `· acceptance did not run`, the error redacted before it is cut), HTTP API error code `acceptance_failed`. `job_result` gains `acceptance {cmd, ran, exit, timed_out, duration_sec, log_tail}` and lists `acceptance.log`; `job_status` shows `acceptance_cmd`; `agent-jobs status <id>` an `accept:` line. Resume reruns it. Store columns `jobs.acceptance_cmd`, `acceptance_started_at`, `acceptance_exit`, `acceptance_duration_sec`, `acceptance_deadline`, `acceptance_pgid`, `timed_out_at` and `schedules.acceptance_cmd` (additive migrations).

The new orchestrator-only MCP tool `owner_replied` (with `job_id`, or all) clears records after the session has written to the owner, whether the line was delivered yet or not (rows are acknowledged, not deleted, so a reply racing the delivery is never undone; with a `job_id` every attempt of the job is acknowledged and its latest finished attempt is pre-acknowledged in one transaction, so a line that begins later holds nothing); a record expires on its own after `owner_waits_max_hours` (config, default 6) and stays expired, so a line whose delivery keeps failing stops holding; rows are pruned only once their attempt can no longer be delivered (job gone, a newer attempt, or finished and notified) and older than the max age. Pending records and the bound session show in `agent-jobs status` (without an id) and `system_doctor` (`owner_reply_pending`, `owner_hook_session`). The README shows how to register both hooks in the orchestrator's `settings.json`; agent-jobs edits no settings file.

Briefs, schedule prompts, titles derived from them (a job schedule without a title, and the jobs it fires, are now titled `schedule <id>`; older `schedule: <prompt>` titles are shown that way), session ids, env, config, error texts (allowlisted `error_code` / `last_error_code` with a fixed message instead), job dirs and repository paths are never returned; string fields are capped at 200 bytes. `report.md` (also for `job_result`) is opened through the state dir with `openat` and `O_NOFOLLOW` at every level; a symlinked `jobs` or job dir, a hard link or a file of another owner is refused. - Codex runner (DEVIATIONS #5): a job with a `gpt-*` model or `runner: codex` (`job_start` field `runner`, `agent-jobs start --runner codex`) runs on `codex exec --json --ignore-user-config --ignore-rules --ephemeral --skip-git-repo-check -s S -c approval_policy="never" -c mcp_servers={} --disable <f>… -m M -c model_reasoning_effort=E -` with the brief on stdin (the owner's codex config, rules, MCP servers, apps and plugins are never inherited; the disabled features are listed in `CodexDisabledFeatures`; before every launch `<codex bin> mcp list --json` must print exactly `[]`, otherwise the job is refused: configured MCP servers are named, an error, a 15 s timeout or other output refuse it too); effort from the job (`reasoning_effort`, `--reasoning-effort`), config `codex_reasoning_effort` or `high`; sandbox `read-only` for review/research, `workspace-write` for fix/general, which is refused unless config `codex_write_allowed: true` (the guard hook does not run inside codex), checked at enqueue and against `config.json` reloaded before every codex launch (an unreadable or invalid config refuses the launch). Config `models` overrides cells of the kind × complexity table (defaults unchanged); config `codex_bin` (env `AGENT_JOBS_CODEX_BIN`). Store column `reasoning_effort`.
- Daily automation (Wave B): the daemon runs `prune` (for real, with the log archive) and `doctor procs` (report only, never kills) once per local day, at the first tick after `daily_hour` (default 4; `daily_off: true` disables). The claimed day is stored in the new `daily` table, so a restart does not repeat it and a missed day runs once. Each step is time-boxed (10 min), runs in a goroutine that never overlaps itself or delays launches, and a failing step (or a panic, also in the doctor procs scan) never stops the other or the tick; a doctor procs scan abandoned at the time-box keeps the daily lock until it ends, and shutdown does not wait for it. Prune runs the archive retention before the per-job pass, so the time-box never starves it; a day earlier than the stored one (clock or TZ step back) is never claimed. The summary is logged and shown by `agent-jobs status` (without an id) and `system_doctor` (`daily`; a failed step is a problem).
- Intentions, the agent's own goals: orchestrator MCP tools `intention_add` (text, optional due date and priority; returns the id), `intention_list` (optional status filter) and `intention_set` (status and/or text, in place; statuses `open`, `done`, `dropped`; no delete), table `intentions` in the agent's store (created on Open, so older databases gain it), text one line (control characters refused) and capped at 500 characters; `agent-jobs intentions --agent A [--status S] [--json]` lists them.
- Schedules (Wave B): orchestrator MCP tools `schedule_add`, `schedule_list`, `schedule_set` (cron, prompt, enabled; in place) and `schedule_remove` (only on the owner's instruction), table `schedules` in the agent's store (created on Open), `agent-jobs schedules --agent A [--json]`. A 5-field cron in local time (ranges, steps, lists, names, macros, the day-of-month / day-of-week rule; own parser, no dependency) plus a one-line prompt (≤ 2000 characters, control and bidi characters refused, `[jobs:` defanged), checked in every daemon tick. Without a kind the prompt is typed into the session as `[jobs:schedule] …`, several due in the same minute as one numbered line («these are different instructions, do each one»); with a kind a job is queued with the model, runner and limits validated like `job_start` (codex rules included) and stored at creation, carrying `schedule_id`. Each firing is claimed in the store before delivery: nothing fires twice (restarts, a clock step back; in the repeated DST hour a local wall-clock watermark fires each wall-clock minute once), a missed minute or a failed delivery is lost, never replayed.

- `notify_owner` (Wave B, DEVIATIONS #4): MCP tool for the orchestrator and the job role, and `agent-jobs notify-owner --agent A --text T [--urgency normal|high]`. agent-jobs sends nothing to a messenger: one line `[jobs:notify-owner] [urgent ·] [job <id>:] <text>` is typed into `notify_tmux_target` on the job-done tmux path and the orchestrator session relays it. Text one line (control and format characters refused), valid UTF-8, capped at 300 characters, `[jobs:` and a leading `[` defanged so it cannot forge a tag. A job calls through the daemon's proxy socket (now served also without a brain; running jobs only, and every proxy op is bound to the calling process: its socket peer pid must be in the named job's session, and in its scope when it has one, so a job cannot act as another). Limits: per job at most 3 and one a minute, per agent at most 20 an hour, checked in one `BEGIN IMMEDIATE` transaction. Every admitted call is stored in the new table `owner_notifications` (a refused one stores nothing) (job id or NULL, text, urgency, created_at, delivered, error; created on Open); a failed delivery keeps the row undelivered with its error, and undelivered rows of the last 24 h show in `agent-jobs status` (without an id) and `system_doctor` (`undelivered_notifications`, a problem). Tmux deliveries are serialized by `<state>/tmux.lock` and bounded by 10 s (lock wait and every tmux call; a timed-out job-done line is retried next tick and never holds the tick); a trailing `;` of a line is escaped for tmux.
- Dead-man's switch (Wave B): checks, a name plus a cron in local time and a grace (default 60 minutes, 1..10080). Orchestrator MCP tools `check_add`, `check_list`, `check_set` (cron, grace, enabled; in place, re-arms) and `check_remove` (only on the owner's instruction); `check_mark` for the orchestrator and the job role (through the daemon's proxy, op `check_mark`); CLI `agent-jobs checks [--json]` and `agent-jobs check mark NAME [--note T]`; tables `checks` and `check_marks` (created on Open). The watchdog runs in every daemon tick: the latest expected time E past its grace is judged once: ok with a mark in (previous E, E + grace], each mark satisfying one expected time only (the earliest not yet counted), missed otherwise. The judgement is stored on the check (evaluation watermark: restart-safe, local wall-clock watermark for DST, conditional on the check's `revision` so a concurrent `check_set` voids it) and never re-judged from marks; marks are pruned only below it. A missed E alerts with `[jobs:check-missed] <name> expected <E> (no mark within <grace>m)` (several in one tick as one line, bounded tmux path, typed after the tick released the lifecycle lock); the alert's delivery state (pending, delivered, failed, attempts, error) is stored, a failed delivery is retried with backoff up to 5 attempts, at-least-once (a crash between typing and storing it may type it twice). Never for expected times before creation or re-arming, and at most once after a long downtime. A `cp`/`install`/`ln`/`mv` destination that is an ancestor of state is refused unless it is `$HOME` itself with plain source names and no `-T`/`--parents` (`cp -r m/. ~/.agent-jobs`, `cp -r x/. ~`, `cp --parents thrall/jobs.db ~/.agent-jobs` are refused; `cp out.txt ~`, `mv out.txt ~` are allowed). SQLite `file:` URIs are also checked percent-decoded and with a `localhost` or empty authority dropped. Here-strings (`python3 <<< "…"`) are checked like here-doc bodies. In inline code, here-docs and `--opt=`/`key=` values a plain ancestor of state below `$HOME` is refused (`shutil.rmtree('<state>')`); free text such as a commit message no longer gets the ancestor rule, and tokens that clean to `/` or `.` are skipped (`print(7 // 2)`, `//` comments, `sed 's,//,/,g'` are allowed again). An interpreter reading its program from a pipe (`echo '…' | sqlite3`, `printf … | python3`) is checked against the earlier stages like `xargs`. When the call may create a symlink, a `..` after a path that does not exist yet is refused (`ln -s ../.. A && ln -s A/.. B`). Ancestor hits inside text use the ancestor message. Third pass: a word up to 4 KB is resolved as one path however many `/` it has (a redirection to a 260-segment word with a space no longer escapes); `cp --pa` counts as `--parents` and the `$HOME` destination exception needs bare source names; `file:` URIs are decoded per valid `%XX`, so a stray `%` (`'%d' % 1`) no longer skips decoding; any python/perl/node/ruby/php/sqlite3 later in a pipe is checked against the earlier stages whatever its options (`python3 -W ignore`, `sqlite3 -separator , x.db`); `..` back out of a missing prefix resolves symlinks again (`n/../S/../jobs.db`). Final pass: a plain operand or redirect target over 4 KB is still resolved as one whole path (a `sqlite3` database name padded with `./` and holding a space is refused). Only a real inline-code argument (`python3 -c`, `perl -e`, `node --eval`, `php -r`, `bash -c`, also `c` inside a flag cluster such as `-ec`, `-xc`, the awk program) over 4 KB is resolved by its tokens: an option ending in `e` no longer makes the next word code (`sqlite3 -table <padded db>` is refused); a pipe feeder into an interpreter gets the strict scan, ancestors included, whatever the interpreter's options (`… | node -p`, `node -e 0 -i`, `node --title x.js` run stdin), so `ls ~ | python3 x.py` and `df -h / | python3 x.py` are refused again (known false refusals, DEVIATIONS #12). Path resolution is linear (`physical` and `resolvePath` walk each segment once, long multi-token code words are resolved by their tokens only), and the check has its own 5 s budget that refuses «too complex to verify» (fail closed).
- Project cards are opened with `openat(O_NOFOLLOW)` relative to the cards directory and read bounded from the same descriptor (no symlink escape, no growth after the size check); front matter selectors and a new card's origin with control characters (CR/LF, …) are refused.
- A job's environment no longer carries `DBUS_SESSION_BUS_ADDRESS` / `XDG_RUNTIME_DIR`; the guard and the deny rules reject `systemd-run`, `systemctl --user`, `busctl`, `dbus-send`, `gdbus`, `qdbus`, `dbus-run-session` (guard also behind wrappers, `xargs`, and as words inside other programs' arguments) and writes into the cgroup file system in any spelling (cleaned, relative, symlinked, through `/proc/<pid>/root`, control-file base names; `cd` into `/sys` or `/sys/fs`), the direct ways out of a job's scope.
- Owner decision 2026-10-17: the guard and the deny rules also reject `crontab`, `at`, `batch`, `tmux`, `screen`, `pm2`, `docker`, `docker-compose`, `podman`, `podman-compose`, `ssh`, `machinectl`, `loginctl`, `unshare`, `nsenter`, `qdbus-qt5`, `qdbus6` (daemons, schedulers and namespaces that run processes outside the job's scope).
- Guard: cgroup-file-system write targets are resolved through variables/backticks (fail closed), `~`, cd/pushd/popd chains in one call (CDPATH, `cd -`), and symlinks to `/`, `/sys`, `/sys/fs`; `cgroup.kill`, `cgroup.freeze` and the other cgroup core files count as control files.
- Guard: a write target (redirection, or an argument of a program that writes: tee, dd, cp, mv, install, ln, rsync, sed, mkdir, touch, rm, …) computed inside the same call is refused as unverifiable in any call, not only when it mentions cgroupfs: a command or process substitution, a variable the call sets (assignment, `read`, `mapfile`/`readarray`, `for`/`select`, `declare`/`export`/`local`/`typeset`/`readonly`, `printf -v`, `${X:=…}`), a positional, indirect or `$_` expansion, any variable after `.`/`source` or `declare -n`, and any write after an `ln` with a variable argument. A plain environment variable (`> "$OUT"`, `tee "$LOG"`, `"${OUT}"`) stays allowed. Note: calls such as `mkdir -p "$(dirname f)"`, `OUT=x.log; make > "$OUT"` or `for f in a b; do echo > "$f"; done` are now refused; write the paths out.
- Guard: `trap` code is parsed like `sh -c` code (it runs later, also after the last command).

## [0.1.0] – 2026-10-17 – Stage 1 core, Linux port, guard hardening, public release

### Added
- SQLite job queue (`jobs` table) with statuses queued/running/succeeded/failed/timeout/cancelled; only queued/running are mutable.
- Limits: defaults 80 turns / $10 / 45 min, ceilings 200 / $50 / 180 – over-ceiling requests rejected, never clamped. At most 2 running jobs per agent.
- `agent-jobs daemon` (tick every minute) and `agent-jobs tick`; launchd template with KeepAlive.
- Launch exactly per the reference via a detached `agent-jobs run-wrapper` in its own process group; exit_code file; a daemon restart neither kills nor loses jobs.
- Per-job git worktree (detached at base) or empty work dir; `base_commit` file.
- settings.json: «nothing outside» deny rules, web tools only for research, PreToolUse guard hook (`agent-jobs guard`).
- prompt.md: preamble + owner rules (≤ 8 KB, required) + task + kind checklist + report contract.
- report.md extracted from stream.jsonl; exit 0 without a report = failed.
- One-line tmux notify `[jobs:job-done] …` (disabled unless configured); undelivered lines stay pending and are retried.
- Cleanup 30 min after notify: diffstat.txt, commits.patch, staged.patch, uncommitted.patch, untracked.tar, `refs/agent-jobs/jobs/<id>`, then removal of only that job's worktree; restore tested.
- `prompts/orchestrator.md` – main-session duties quoted verbatim from the reference (read the report, «Not done / uncertain» first, check the diff, publish only after; cleanup/patches); `agent-jobs init` writes it to `<state>/orchestrator.md`.
- CLI: init, start, status, list, result, cancel, `version` (also `--version`; the version is set at build time with `-ldflags "-X main.version=…"`, `dev` otherwise).
- Linux support: systemd user unit template `deploy/systemd/agent-jobs@.service` (instance = agent, `KillMode=process`, `Restart=on-failure`, env file `$XDG_CONFIG_HOME/agent-jobs/<agent>.env`) and `scripts/install-linux.sh` (idempotent build/install/enable/restart, `--uninstall`, no sudo, current user only; stamps the binary with `git describe --tags --always --dirty`).
- Tests for the unit template and the install script (fake systemctl, sandboxed HOME), including `systemd-analyze --user verify` of the template when available.
- Local checks: `scripts/check.sh`, `.githooks/pre-push`.
- Docs: English README with a Russian version (`README.ru.md`), English translation of the reference design (`docs/REFERENCE.md`, original in `docs/REFERENCE.ru.md`), public roadmap (`docs/PLAN.md`, `docs/PLAN.ru.md`), `docs/DECISIONS.md`, DEVIATIONS #11 (systemd user service on Linux), diagrams in `docs/images/`, MIT `LICENSE`.

### Changed
- Model table: review/fix/general light → sonnet, normal → opus, hard → `fable`; research light/normal → sonnet, hard → opus.
- Reference timings fixed: daemon `--interval` removed (tick every minute), `cleanup_delay_minutes` removed (cleanup 30 min after notify); a config that still sets it is rejected.
- Preamble wording 1:1 with the reference – no «unless the brief names a path» exception.

### Fixed
- Per-agent `flock` around tick and cancel; atomic claim with a launch token; a tick only finishes jobs it owns.
- Claim before spawn; the wrapper registers in `wrapper.json` before running claude and holds `wrapper.lock`; the next tick adopts an orphan wrapper; a claim whose wrapper never registered fails loudly after 1 minute.
- stream.jsonl is read after exit_code is seen.
- Cleanup no longer touches the index, and verifies worktree ownership (worktree.json + porcelain listing + owner mark in the admin dir) before touching anything.
- `--uninstall` keeps the binary while job wrappers started from it run (it is their guard hook; exit 1 with «N jobs still running»); «other instances» also counts active-but-not-enabled `agent-jobs@` units.
- Installer: env file parsed (`KEY=VALUE` only), never sourced; `umask 077` scoped to the env-file write; installer lock (`flock -n`); unit written via tmp + rename; warning on a non-default `XDG_CONFIG_HOME`.

### Security
- Job-done line is printable-only (control/format characters dropped, whitespace → space, title ≤ 120 runes), so a title cannot type keystrokes into the session.
- Guard parses Bash commands and blocks git push/tag and gh release/api/pr/issue writes in any spelling (global options, quotes, paths, env prefixes, wrappers, substitutions, `sh -c`, `eval`, `-R`, aliases).
- Guard fails closed: a program not positively classified as data-only is rejected when a git/gh or shell word is among its arguments (closes awk `system()`, `vim -c '!…'`, `docker exec`, `python3 -W ignore -c`, `rg --pre`, `man -P` and similar). Shell detection is case-insensitive and covers csh/tcsh/ash/mksh/fish; `busybox` is a wrapper, `nix-shell --run` is parsed like `sh -c`.
- gh is checked against a read-only allowlist; gh flags before the subcommand other than `-R`/`--repo`/`--hostname` are rejected; `gh auth status` is not allowed.
- `git commit -C/-c`, `--reuse-message`, `--reedit-message`, `--fixup`, `--squash` and abbreviated long options are rejected; `-t/--template` files are checked like `-F`; pipefail state is tracked; commit message and identity checks parse real arguments; `pgrep -f` is blocked only when its pattern matches its own loop.
- File tools (Write/Edit/MultiEdit/NotebookEdit) cannot write inside `.git` or the job's own git dirs (symlinks resolved, `..` rejected).
- Wrapper starts claude with a scrubbed git environment (job-only global config with the job identity, no system config, hooks/fsmonitor/ssh/credential helper/pager/editor overridden); the daemon's own git calls use the same overrides, and cleanup makes no patch when the repository config names a filter, diff command or textconv.
