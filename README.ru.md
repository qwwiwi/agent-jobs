## Один бриф на входе. Готовая работа на выходе.

**Agent Jobs превращает одну сессию Claude Code в тимлида.** Вы один раз ставите сессии большую задачу. Она пишет брифы и отдаёт работу фоновым *джобам* `claude -p`. Каждая джоба работает сама в своём git worktree, под жёсткими лимитами и гвардом, и возвращается с отчётом. Сессия сверяет результат с чек-листом, который утвердил владелец, и выпускает работу, только когда выполнено каждое требование. Вы участвуете только на этапе утверждения плана.

- **Дешевле.** Долгоживущая сессия остаётся лёгкой: она платит за одну строку, когда джоба закончилась, и за одно чтение отчёта. Ей не нужно перечитывать дампы файлов исполнителя на каждом следующем вызове.
- **Быстрее.** Сессия никогда не ждёт исполнителя. Джобы идут в параллельных слотах, остальные ждут в очереди, и они переживают перезапуск сессии или демона.
- **Лучше.** Каждая джоба — полноценный запуск Claude Code верхнего уровня со своим контекстом и фиксированным контрактом отчёта. Большие задачи проверяются по чек-листу владельца строка за строкой, с доказательствами и red proof. Проверяет слепой судья на другой модели.
- **Автономно.** Лимиты на ходы, деньги и время, гвард на каждом вызове инструмента, одно автоматическое продолжение после остановки по лимиту ходов или таймауту, расписания и проверки dead-man's switch. Ничего не уходит наружу, пока сессия не прочитала отчёт и не проверила дифф.

Это один бинарник на Go и один файл SQLite на агента. Работает на Linux (пользовательская служба systemd) и macOS (launchd).

## Быстрый старт

Нужны Go 1.27, git, CLI `claude` и tmux (для строки о завершении джобы).

**1. Установка (Linux).** Один скрипт собирает бинарник, ставит пользовательский юнит systemd и скилл `agent-jobs`, инициализирует агента и запускает демон:

```bash
git clone https://github.com/qwwiwi/agent-jobs && cd agent-jobs
scripts/install-linux.sh --instance my-agent
systemctl --user status agent-jobs@my-agent
```

На macOS: соберите `go build -o ~/.local/bin/agent-jobs ./cmd/agent-jobs`, выполните `agent-jobs init --agent my-agent` и загрузите шаблон launchd, см. [Установка и настройка](docs/GUIDE.ru.md#установка-и-настройка).

**2. Укажите, где живёт сессия.** В `~/.agent-jobs/my-agent/config.json` укажите tmux-цель вашей сессии Claude Code, чтобы до неё доходила строка о завершении джобы:

```json
{ "notify_tmux_target": "my-agent-session" }
```

Затем отредактируйте `~/.agent-jobs/my-agent/owner-rules.md` (ваши постоянные правила для каждой джобы, ≤ 8 КБ) и добавьте `~/.agent-jobs/my-agent/orchestrator.md` (обязанности главной сессии) в инструкции агента.

**3. Дайте сессии инструменты.** Сессия управляет джобами через MCP-сервер на stdio; зарегистрируйте его в MCP-конфиге сессии:

```json
{ "mcpServers": { "agent-jobs": { "command": "agent-jobs", "args": ["mcp", "--role", "orchestrator", "--agent", "my-agent"] } } }
```

**4. Первая джоба.** Попросите сессию её запустить (`job_start`) или воспользуйтесь CLI:

```bash
agent-jobs start  --agent my-agent --title "review auth" --kind review \
  --repo ~/src/project --base main --complexity normal --brief-file brief.md   # сразу печатает id джобы
agent-jobs list   --agent my-agent
agent-jobs result --agent my-agent <id>   # строка о завершении + report.md
```

Каждой джобе нужен `--model` или `--complexity`. Полная настройка (все ключи конфига, общий мозг, HTTP API, обновления, macOS): [docs/GUIDE.ru.md → Установка и настройка](docs/GUIDE.ru.md#установка-и-настройка).

## Зачем agent-jobs

**Делегируйте большие задачи, а не только мелкие поручения.** Всё, что дольше нескольких шагов, становится джобой: код, циклы исправлений, ревью, исследования, ночная работа. У джобы свой git worktree, свои лимиты (по умолчанию 80 ходов, $10, 45 минут) и гвард на каждом вызове инструмента. В конце она обязана сдать отчёт в фиксированном формате. Следить за ней никому не нужно.

**Каждая джоба работает сама.** Джоба — отдельный процесс с собственным полным контекстом. Она коммитит локально и никогда не пушит, ничего не публикует и никому не пишет. Она переживает перезапуск сессии или демона. Джоба, остановленная по лимиту ходов или таймауту, один раз продолжается автоматически, а остановленную джобу можно продолжить в той же сессии с новыми указаниями.

<p align="center"><img src="docs/images/swarm.png" alt="Главная сессия раздаёт работу многим джобам и получает от каждой галочку" width="100%"></p>

**Главная сессия оркестрирует.** Она разговаривает с владельцем, пишет каждой джобе бриф (разговора джоба не видит), запускает её и возвращается к работе. Когда джоба закончилась, сессия читает отчёт (сначала «Not done / uncertain») и проверяет дифф от базового коммита. Только после этого она решает и пушит, мержит или деплоит. Наружу выходит только она. Маршрутизация и конвейер на каждый день: [docs/WORKFLOW.ru.md](docs/WORKFLOW.ru.md).

**Экономит контекст.** Результат субагента попадает в родителя и перечитывается на каждом следующем вызове. Джоба пишет результат в файл, а родитель получает одну строку. Это важно, потому что основная цена — долгоживущий контекст. За пять дней реальной работы главная сессия одного агента перечитала из кеша около **7,2 млрд** токенов, а все её субагенты вместе — около **2,3 млрд** ([подробнее](docs/GUIDE.ru.md#почему-джобы-а-не-субагенты)).

**Экономит время и работает быстрее.** Исполнитель никогда не блокирует сессию. В [бенчмарке](docs/BENCHMARK.md) родитель был занят 0,73 мин на джобу против 1,65 мин для субагента на переднем плане (0,47 мин для фонового). Джобы идут рядом в `max_running` слотах на агента (по умолчанию 2, до 8), каждая в своём worktree, остальные ждут в очереди. Честно: на маленькой задаче одна джоба дешевле не выходит — она обошлась на 28–35% дороже (по расчётной стоимости) и шла в два-три раза дольше, чем субагент. Выигрыш — свободная сессия, жёсткие лимиты, изоляция и параллельная работа. Все цифры: [docs/BENCHMARK.md](docs/BENCHMARK.md).

## Большие задачи: от одного брифа до проверенного релиза

<p align="center"><img src="docs/images/brief-flow.png" alt="Бриф, чек-лист, джобы, самопроверка, релиз: один бриф на входе, готовая работа на выходе" width="100%"></p>

Для большой задачи (новый проект или фича с более чем 5 требованиями, несколькими джобами или работой дольше дня) agent-jobs держит слова владельца контрактом от начала до конца:

1. **Бриф.** `checklist_init` дословно сохраняет слова владельца в `brief/BRIEF.md` в репозитории проекта (секреты замаскированы). Этот текст заморожен. Более поздние слова владельца добавляются под `## Additions` как цитаты с датой.
2. **Чек-лист.** Сессия выводит из брифа пронумерованные строки `brief/CHECKLIST.md` через `checklist_set`. У каждой строки есть ID (`R01` из брифа, `R01i` подразумеваемое, `G01` добавлено владельцем позже, `D01` ограничение), цитата из брифа, из которой она взята, и контракт (`live`, `placeholder-ok`, `deferred`, …).
3. **Вопросы.** По желанию `briefing_start` запускает read-only джобу. Она готовит для владельца один-два раунда не больше чем по четыре вопроса. У каждого вопроса есть предложенный ответ, и он называет строки, которые закрывает.
4. **Слепая проверка нарезки.** `slicing_start` запускает read-only джобу, которая видит только бриф и строки. Она перечисляет цитаты брифа, которые не покрыты ни одной строкой, цитаты, покрытые наполовину, и строки, которых нет в брифе. По каждой непокрытой цитате владелец обязан принять решение.
5. **Утверждение владельцем.** `checklist_set approve` сохраняет утверждение со словами владельца и привязывает его к хешу строк и брифа. Любая последующая правка его аннулирует.
6. **Джобы покрывают строки.** Каждая джоба фичи запускается с `covers` (ID строк, над которыми работает) и `size: large`. Демон дословно вписывает покрытые строки в промпт джобы. Джоба обязана отчитаться строкой по каждому требованию: доказательство, выполненная команда и red proof (тест, который падал до изменения). Строка `done` без них считается *заявленной*, а не выполненной.
7. **Слепой судья.** `judge_start` даёт read-only джобе копию кода на коммите, без истории, диффов и отчётов. Перед судьёй джоба запускает на этой копии `scripts/manifest-check.sh` репозитория. Судья выносит вердикт по каждому live-требованию и должен работать на другом семействе моделей, чем кодеры.
8. **Релиз только при 100%.** `release_check` пропускает, только когда выполнено каждое live-требование (или это заглушка на строке `placeholder-ok`, или владелец снял его именно для этого коммита). Каждая цитата брифа должна быть покрыта, судья должен быть слепым и из другого семейства моделей, а каждое требование — прослеживаться до джобы. Владельцу он сообщает «Acceptance: N of M». Хук `merge-gate` блокирует `gh pr merge`, пока эта проверка не прошла на точном head-коммите.

Подробности: [чек-лист брифа, нарезка, судья, release check](docs/GUIDE.ru.md#mcp-тулы) и [docs/PLAN.ru.md](docs/PLAN.ru.md) (волна F).

## Возможности кратко

| возможность | что это | зачем это вам |
|---|---|---|
| [Джобы](docs/GUIDE.ru.md#как-это-работает) | одноразовые запуски `claude -p` в своём git worktree, через `job_start` или `agent-jobs start` | тяжёлая работа уходит из сессии, назад приходит одна строка |
| [Очередь и лимиты](docs/GUIDE.ru.md#лимиты) | не больше `max_running` джоб на агента; лимиты на ходы, деньги и время; модель или сложность на каждую джобу; явный reasoning effort | параллельная работа с предсказуемыми затратами; запрос выше лимита отклоняется, а не урезается |
| [Дополнить, остановить, продолжить](docs/GUIDE.ru.md#сменить-курс-дополнить-остановить-продолжить) | дополнить джобу в очереди, остановить идущую с сохранением worktree и сессии, продолжить её с новыми указаниями, одно автопродолжение | смена курса без потери того, что джоба уже знает |
| [Гвард и безопасность](docs/GUIDE.ru.md#безопасность) | deny-правила, PreToolUse-гвард с разбором команд, очищенное git-окружение, read-only ревью-джобы, cgroup-scope на Linux, никаких вложенных джоб | джоба никогда не пушит, не публикует и никому не пишет |
| [Контракт отчёта](docs/GUIDE.ru.md#контракт-отчёта) | Summary, Findings / Changes, Evidence, Not done / uncertain, Progress; секреты вычищаются из отчётов | каждый результат читается одинаково, пробелы — первыми |
| [Чистка и патчи](docs/GUIDE.ru.md#чистка-и-патчи) | worktree удаляется через 30 минут после строки о завершении, работа хранится патчами и git-ref; prune, архив логов, статистика по джобам | диск чистый, работа не теряется |
| [Скиллы и контекст джобы](docs/GUIDE.ru.md#скилл-субагенты-и-контекст-джобы) | скилл `agent-jobs` для сессии; правила владельца, карточки проектов и скиллы из каталога для джоб | сессия правильно маршрутизирует работу, а джобы стартуют с нужным контекстом |
| [Расписания](docs/GUIDE.ru.md#mcp-тулы) | cron по местному времени: напечатать промпт в сессию или запустить джобу | регулярная работа без человека |
| [Проверки (dead-man's switch)](docs/GUIDE.ru.md#mcp-тулы) | работа, которая молчит, пока здорова, оставляет отметку; пропущенная отметка поднимает тревогу в сессии | тихие сбои не проходят незамеченными |
| [notify_owner](docs/GUIDE.ru.md#mcp-тулы) | джоба или сессия зовёт владельца через собственный канал сессии | джоба может поднять руку, с ограничением частоты |
| [Владелец ждёт](docs/GUIDE.ru.md#mcp-тулы) | Stop-хук держит ход сессии, пока она не ответила владельцу о джобе, которую он заказывал | владелец всегда получает ответ |
| [Heartbeat](docs/GUIDE.ru.md#установка-и-настройка) | демон будит сессию ради её собственных целей, вне ночного окна и в пределах дневного лимита | агент сам двигает свои цели |
| [Свои цели](docs/GUIDE.ru.md#mcp-тулы) | собственные цели агента: добавить, перечислить, сменить статус | цели переживают разговор |
| [Общая память (мозг)](docs/GUIDE.ru.md#установка-и-настройка) | тулы памяти, задач и команды поверх общего мозга команды; заметки памяти в каждом брифе | джобы и агенты делятся тем, что узнали |
| [HTTP API только для чтения](docs/GUIDE.ru.md#установка-и-настройка) | health, джобы, статистика, расписания и скиллы через unix-сокет или loopback, нужен токен | дашборд без доступа к базе |
| [Раннер Codex](docs/GUIDE.ru.md#лимиты) | модель `gpt-*` запускает джобу на `codex exec`; по умолчанию только чтение, с дневным лимитом | второе семейство моделей для ревью и судейства |
| [Поток брифа](#большие-задачи-от-одного-брифа-до-проверенного-релиза) | бриф, чек-лист, вопросы, проверка нарезки, утверждение, covers, судья, release check, merge gate | большие задачи с одного брифа, релиз только при 100% |
| [Doctor, логи, активность](docs/GUIDE.ru.md#mcp-тулы) | `system_doctor`, `system_logs`, `activity_report`, `agent-jobs doctor procs` | видно, что не так, до того как это ударит |
| [Корзина](docs/GUIDE.ru.md#mcp-тулы) | обратимое удаление внутри заданных корней: `trash_move`, `trash_restore` | удаление без `rm` |

## Как это работает

<p align="center"><img src="docs/images/architecture.png" alt="Главная сессия, демон, джоба, папка джобы, владелец и расписания" width="100%"></p>

**Главная сессия** запускает джобы и проверяет их работу. **Демон** тикает раз в минуту. Он запускает джобы из очереди, собирает завершённые, доставляет строки о завершении и подчищает, а состояния в памяти не держит. **Очередь** — одна таблица SQLite на агента. Каждая **джоба** запускает `claude -p` в своей группе процессов и своём git worktree, а в её **папке** лежат бриф, настройки, поток событий, отчёт и патчи. **Расписания** и **проверки** работают на том же тике.

<p align="center"><img src="docs/images/lifecycle.png" alt="job_start, в очереди, идёт, отчёт, строка о завершении, job_result, ревью и пуш, чистка" width="100%"></p>

`job_start` ставит джобу в очередь и сразу возвращает её id. Демон запускает её, когда освобождается слот, и джоба пишет `report.md`. Сессия получает одну строку:

```
[jobs:job-done] job 261015-124136-70d3 review auth module succeeded · 3 turns · $0.25 · 0m · model sonnet · effort high
```

Сессия читает отчёт через `job_result`, проверяет дифф и пушит. Через тридцать минут worktree убирается, а работа сохраняется патчами. Для джобы в репозитории строка ещё говорит, сливаются ли коммиты джобы с веткой без конфликтов. Полный жизненный цикл, компоненты и проверка слияния: [docs/GUIDE.ru.md → Как это работает](docs/GUIDE.ru.md#как-это-работает).
