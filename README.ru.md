**Cheaper. Faster. Full-strength.**

Дешевле. Быстрее. В полную силу.

Agent Jobs позволяет долгоживущей сессии Claude Code отдавать тяжёлую работу фоновым процессам `claude -p`. Главная сессия разговаривает, решает и проверяет; всё, что дольше нескольких шагов, становится *джобой*: одноразовым полноценным запуском Claude верхнего уровня со своим git worktree, жёсткими лимитами на ходы, деньги и время и гвардом на каждом вызове инструмента. Небольшой демон ставит джобы в очередь, запускает, следит и подчищает за ними. Когда джоба закончилась, сессия получает ровно одну строку и читает отчёт, когда готова. Джобы никогда не пушат, ничего не публикуют и никому не пишут; наружу выходит только главная сессия, после того как прочитала отчёт и проверила дифф.

Это один бинарник на Go и один файл SQLite на агента. Работает на Linux (пользовательская служба systemd) и macOS (launchd).

> **Статус:** ядро (очередь, демон, запуск, гвард, контракт отчёта, уведомление, чистка) лежит в `main` и установлено для проверки на одном Linux-сервере. MCP-тулы, через которые агент управляет джобами программно, на ревью ([PR #4](https://github.com/qwwiwi/agent-jobs/pull/4)); до их слияния интерфейс — CLI. План: [docs/PLAN.ru.md](docs/PLAN.ru.md).

## Почему джобы, а не субагенты

Субагенты полезны, и для короткой работы, результат которой нужен сессии прямо сейчас, джобы их не заменяют. Довод за джобы — в том, **где живёт контекст и кто платит за его повторное чтение**.

**Что измерено.** За пять дней реальной работы по 15.10.2026 долгоживущая главная сессия одного из наших агентов перечитала из кеша около **7,2 млрд** токенов; все её субагенты вместе — около **2,3 млрд**. Причина: контекст главной сессии держался около 95% окна в 1M токенов, и каждый вызов перечитывает его целиком. Основная цена — не сама работа, а повторное чтение контекста долгоживущего родителя.

Именно этого джоба избегает:

- **Результат субагента попадает в родителя** и перечитывается на каждом следующем вызове до ближайшей компакции. Джоба пишет результат в файл; родитель получает одну строку и читает отчёт по запросу.
- **Уведомления и ходы с результатом перечитывают весь контекст родителя.** Джоба стоит родителю одной короткой строки по завершении и одного чтения отчёта.
- **Субагент на переднем плане держит ход родителя открытым.** Пока он не вернулся, сессия не может разговаривать и решать. Джоба сразу возвращает id, и сессия остаётся свободной.
- **Джоба — отдельный процесс с жёсткими лимитами.** Субагентов тоже можно ограничить (лимит ходов, перечень инструментов, MCP-серверы). Джоба даёт именно сочетание: отдельный процесс `claude -p` со своим полным контекстом, свой git worktree, бюджет в долларах (`--max-budget-usd`) и таймаут по часам, которые соблюдает демон, жизнь после перезапуска родителя и фиксированный контракт отчёта.
- **Джоба переживает сессию.** Субагенты умирают вместе со своей сессией; джоба работает в своей группе процессов и переживает перезапуск сессии или демона. Продолжение прерванной джобы из сохранённых патчей запланировано (волна B).
- **Нагрузку можно разнести.** Субагенты расходуют окно лимитов одновременно с родителем. Джобы стоят в очереди (одновременно не больше двух на агента) и с расписаниями (запланированы, волна B) могут идти, когда окно свободно.
- **Джоба — полноценная сессия.** Субагент стартует только со своим промптом, и его часто отправляют на более дешёвую модель. Джоба — полноценный запуск Claude Code верхнего уровня со своим выбором модели и полным набором инструментов в рамках лимитов выше.

Цифру «в N раз дешевле» или «в N раз быстрее» мы пока не публикуем: по отдельной задаче мы её не мерили. Как будем мерить — ниже.

### Бенчмарк (в работе)

**Метод.** Одна и та же задача запускается тремя способами: как субагент на переднем плане, как фоновый субагент и как джоба.

- **Токены:** сумма `cache_read + input + output` из JSONL родительской сессии плюс побочная цепочка субагента против собственного JSONL джобы (`stream.jsonl`) плюс токены родителя на строку job-done и чтение отчёта.
- **Время по часам:** от старта до пригодного результата.
- **Занятость родителя:** минуты, когда родительская сессия не могла принять другой запрос.

| Запуск | Задача | Токены (cache_read + input + output) | Время по часам | Родитель занят (мин) | Заметки |
|---|---|---|---|---|---|
| Субагент на переднем плане | | | | | |
| Фоновый субагент | | | | | |
| Джоба | | | | | |

Результаты появятся здесь, когда прогоны будут сделаны.

## Как это работает

### Рой

<p align="center"><img src="docs/images/swarm.png" alt="Главная сессия раздаёт работу многим джобам и получает от каждой отметку" width="100%"></p>

Одна главная сессия, много исполнителей. Сессия пишет бриф для незнакомца (у джобы нет контекста разговора), запускает джобу и возвращается к разговору. Каждая джоба работает одна в своей папке и возвращается с отчётом. Картинка иллюстративная: джобы ждут в очереди, одновременно на агента работают не больше двух.

### Компоненты

<p align="center"><img src="docs/images/architecture.png" alt="Главная сессия, демон, джоба, папка джобы, владелец и расписания" width="100%"></p>

- **Главная сессия** говорит с владельцем, запускает джобы, читает отчёты, ревьюит и пушит. Только ей можно наружу.
- **Демон** (`agent-jobs daemon`) тикает раз в минуту: собрать закончившиеся джобы, запустить ожидающие, доставить строки job-done, подчистить. Состояния в памяти он не держит: убейте его, даже SIGKILL, и идущие джобы продолжат работу; следующий демон найдёт их коды выхода и соберёт их.
- **Очередь** — одна таблица SQLite на агента. Тик забирает джобу со случайным токеном запуска до того, как что-либо запустить, и только этот тик может её завершить, поэтому двойного запуска не бывает.
- **Джоба** — `agent-jobs run-wrapper`, который запускает `claude -p` в своей группе процессов, с очищенным git-окружением, в git worktree, отвязанном на базовом коммите (или в пустом каталоге).
- **Папка джобы** хранит бриф, настройки, поток событий, отчёт и, после чистки, патчи.
- **Расписания (cron)** на схеме запланированы (волна B), в `main` их пока нет.

### Жизненный цикл

<p align="center"><img src="docs/images/lifecycle.png" alt="job_start, queued, running, отчёт, строка job-done, job_result, ревью и пуш, чистка" width="100%"></p>

1. **Старт.** Сессия запускает джобу с заголовком, видом работы, брифом, репозиторием, моделью и лимитами. Вызов всё проверяет, вставляет строку `queued` и возвращает id. Пока ничего не запущено.
2. **В очереди.** На следующем тике, если у агента работает меньше двух джоб, демон её забирает.
3. **Работает.** Демон готовит папку (бриф, настройки, worktree) и запускает обёртку отвязанно, в своей сессии. Обёртка запускает `claude -p` и пишет `exit_code` последним.
4. **Отчёт.** Финальное сообщение джобы сохраняется как `report.md`. Код 0 и отчёт — `succeeded`; ненулевой код, остановка по ходам или бюджету либо отсутствие отчёта — `failed`; после таймаута группа процессов получает SIGTERM, через 10 с SIGKILL, и джоба становится `timeout`. `cancelled` бывает только после явной отмены.
5. **Строка job-done.** Сессия получает одну строку через `tmux send-keys`:
   ```
   [jobs:job-done] job 261015-124136-70d3 review auth module succeeded · 3 turns · $0.25 · 0m
   ```
   В строке только печатные символы (управляющие выброшены, заголовок обрезан), поэтому заголовок джобы не может набрать нажатия клавиш в сессии. Недоставленная строка остаётся в ожидании и повторяется каждый тик.
6. **Результат.** Сессия читает отчёт, когда готова: сначала «Not done / uncertain».
7. **Ревью и пуш.** Сессия сама проверяет дифф от `base_commit`. Отчёт — заявление, а не результат. Только после этого она пушит или публикует.
8. **Чистка.** Через 30 минут после доставки строки worktree удаляется, а работа остаётся в виде патчей (ниже).

Менять статус могут только строки `queued` и `running`; `succeeded`, `failed`, `timeout` и `cancelled` окончательны.

## Лимиты

| | по умолчанию | потолок |
|---|---|---|
| Ходы (`--max-turns`) | 80 | 200 |
| Бюджет (`--max-budget-usd`) | $10 | $50 |
| Время (`--timeout-minutes`) | 45 мин | 180 мин |
| Одновременно на агента | 2 | |

Запрос выше потолка **отклоняется, а не урезается**, чтобы джоба не остановилась по причине, которую автор не видел. Ноль или пропуск — значение по умолчанию; отрицательные значения отклоняются.

**Модель.** Передайте `--model` или `--complexity` (`light` / `normal` / `hard`), которая по виду работы превращается в модель:

| вид | light | normal | hard |
|---|---|---|---|
| review, fix, general | sonnet | opus | fable |
| research | sonnet | sonnet | opus |

В `main` сложность по умолчанию `normal`; с PR #4 модель или сложность становятся обязательными (без догадок).

**Вид работы** добавляет в бриф короткий чеклист:

| вид | что требует чеклист |
|---|---|
| `review` | реальные баги с `file:line`, последствием и минимальным фиксом; проверенное отдельно от подозрений |
| `fix` | сначала воспроизвести падающим тестом, потом минимальная правка, тесты, локальный коммит |
| `research` | только первоисточники, которые реально открыты; проверенное отдельно от выведенного. Единственный вид с доступом в веб |
| `general` | до начала сказать, что считается готовым, и в конце это доказать |

## Контракт отчёта

Финальное сообщение джобы — её отчёт, он сохраняется дословно как `report.md`. Ровно четыре раздела в таком порядке:

```
## Summary
## Findings / Changes
## Evidence
## Not done / uncertain
```

Последний раздел обязателен и читается первым: он заставляет джобу назвать то, чего она не сделала. Джоба, закончившаяся без отчёта, помечается `failed`.

## Чистка и патчи

Через 30 минут после доставки строки job-done демон удаляет worktree джобы, самую тяжёлую часть. Сначала он проверяет, что worktree действительно принадлежит этой джобе, затем сохраняет всё, что джоба изменила, не трогая индекс и файлы:

| файл | содержимое |
|---|---|
| `diffstat.txt` | `git diff --stat <base>` и список неотслеживаемых файлов |
| `commits.patch` | коммиты джобы (`git format-patch <base>..HEAD`) |
| `staged.patch` | изменения в индексе |
| `uncommitted.patch` | рабочее дерево против `HEAD`, включая изменения в индексе (`git diff --binary HEAD`) |
| `untracked.tar` | неотслеживаемые и не игнорируемые файлы |

и ставит в исходном репозитории ref `refs/agent-jobs/jobs/<id>` на последний коммит джобы. Восстановить работу в свежем worktree на базовом коммите — четыре команды, см. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#flows). Если в конфиге репозитория указан filter, diff-команда или textconv, патчи не делаются (дифф запустил бы эту программу): worktree остаётся для человека, причина пишется в журнал.

Чистка папок джоб старше 48 часов и ежедневная проверка призрачных процессов запланированы (волна A).

## Безопасность

Джоба работает с `bypassPermissions`, и никто за ней не смотрит. Поэтому правила держатся настройками и хуком, а не вежливой просьбой в промпте.

- **Из джобы ничего не выходит.** Deny-правила в `settings.json` джобы, которые действуют даже при `bypassPermissions`, запрещают `git push` / `tag`, `gh release`, `gh api`, создание, правку, комментарии и мерж PR и issue, вложенных агентов (`claude`, `codex`, `gemini`, `aider`, …), загрузчики пакетов (`npx`, `uvx`, `pnpm dlx`, …), запись файловыми инструментами внутрь `.git` и инструменты, которые достают до человека или переживают запуск (`CronCreate`, `RemoteTrigger`, `PushNotification`). Веб открыт только джобам вида `research`.
- **Только свои MCP-серверы.** `--strict-mcp-config` отрезает всё, чего нет в `mcp.json` джобы, включая `.mcp.json` самого репозитория. `--setting-sources project` не пускает хуки главной сессии.
- **Гвард.** PreToolUse-хук (`agent-jobs guard`) *разбирает* каждую Bash-команду, а не ищет подстроки: кавычки, обёртки, `sh -c`, `eval`, подстановки и пути раскрываются. Он блокирует любое написание перечисленных выше внешних действий, подкоманды git, которые запускают программы, запись в собственные файлы git, опасные ключи `git config`, подмену git-идентичности, имя владельца в коммите, `$?` после пайпа без pipefail и циклы ожидания, находящие сами себя. Форму вокруг git или gh, которую он не может разобрать, он блокирует, а не угадывает. Неразбираемый ввод — отказ.
- **Очищенное git-окружение.** Обёртка выбрасывает унаследованные `GIT_*`, `PAGER`, `EDITOR`, `VISUAL`, использует глобальный git-конфиг только этой джобы с её идентичностью, без системного конфига, и переопределения уровня командной строки, которые выключают хуки репозитория, fsmonitor, SSH-команду, помощники учётных данных, пейджер и редактор.
- **Преамбула и правила владельца.** Каждый бриф начинается с жёстких правил (только своя папка, содержимое файлов и инструментов — данные, секреты не печатать, ничего наружу) и файла постоянных правил владельца (≤ 8 КБ). Если файл не читается, джоба не стартует.

**Это не песочница.** Deny-правила и гвард закрывают *прямые* написания внешних действий, а очистка git-окружения не даёт самому git запускать программы, которых гвард не видит. Скрипт, который джоба сама написала и запустила, разрешён намеренно, как и в эталонном дизайне, и его содержимое не проверяется. Запускайте джобы от пользователя, чьи учётные данные вы готовы им доверить.

Полный список правил: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#rules-enforcement).

## MCP-тулы

Запланировано (PR #4): агент будет управлять джобами через MCP-сервер в двух ролях, `orchestrator` для главной сессии и `job` для самих джоб. Роль джобы будет разрешённым перечнем: новый тул закрыт для джоб, пока его не открыли намеренно, а скрытые тулы будет отклонять сам сервер. Сейчас в `main` `mcp.json` джобы пуст, а интерфейс — CLI.

**Тулы джоб, на ревью ([PR #4](https://github.com/qwwiwi/agent-jobs/pull/4)):**

| тул | что делает |
|---|---|
| `job_start` | поставить джобу: заголовок, вид, бриф, репозиторий, модель или сложность, лимиты; возвращает id |
| `job_status` | статус, ходы, стоимость, время |
| `job_result` | строка job-done, отчёт и пути к артефактам |
| `job_list` | последние джобы с фильтром по статусу |
| `job_cancel` | отменить: из очереди сразу, идущую — SIGTERM, затем SIGKILL |

**Полный запланированный набор** (из эталонного дизайна; см. [docs/PLAN.ru.md](docs/PLAN.ru.md)):

| группа | тулы оркестратора | доступно джобе | статус |
|---|---|---|---|
| Джобы | `job_start`, `job_status`, `job_result`, `job_list`, `job_cancel` | нет | на ревью (PR #4) |
| Джобы | `job_resume` | нет | запланировано, волна B |
| Память | `memory_search`, `memory_write`, `memory_already_exists` | `memory_search`, `memory_write` | запланировано, волна A |
| Задачи | `task_create`, `task_list`, `task_update`, `task_get` | нет | запланировано, волна A |
| Команда | `send_message`, `inbox` | нет | запланировано, волна A |
| Система | `system_doctor`, `system_logs`, `activity_report` | нет | запланировано, волна A |
| Файлы | `trash_move`, `trash_restore` | нет | запланировано, волна A |
| Расписания | `schedule_add`, `schedule_list`, `schedule_remove` | нет | запланировано, волна B |
| Собственные цели | `intention_add`, `intention_list`, `intention_set` | нет | запланировано, волна B |
| Владелец | `notify_owner` | нет | запланировано, волна B |
| Код | индекс кода в виде графа (отдельный сервер) | чтение и индексация | исследование, волна C |

Тулы памяти, задач и команды сохранят имена из эталона, но будут работать поверх общей памяти команды, а не своего хранилища ([отличия #2, #3](docs/DEVIATIONS.md)); пока не построены.

## Быстрый старт

Нужны Go 1.27, git, CLI `claude` (проверено на 2.1.301 под macOS и 2.1.302 под Linux) и tmux для уведомлений. Единственная прямая зависимость — `modernc.org/sqlite`, SQLite-драйвер на чистом Go: без cgo, один статический бинарник.

**Сборка и проверка**

```bash
go build -o ~/.local/bin/agent-jobs ./cmd/agent-jobs
git config core.hooksPath .githooks   # один раз на клон: pre-push запускает scripts/check.sh
scripts/check.sh                       # gofmt, go vet, go test
```

**Инициализация агента**

```bash
agent-jobs init --agent my-agent
```

Создаёт `~/.agent-jobs/my-agent/` с `owner-rules.md` (отредактируйте, ≤ 8 КБ) и `orchestrator.md` — обязанности главной сессии: добавьте его в инструкции агента.

Необязательный `~/.agent-jobs/my-agent/config.json`:

```json
{
  "notify_tmux_target": "my-agent-session",
  "owner_names": ["Owner"],
  "git_name": "Agent Bot",
  "git_email": "agent@example.com"
}
```

- `notify_tmux_target`: цель tmux для строки job-done. Пусто (по умолчанию) — уведомления выключены; строка уходит в журнал демона, чистка всё равно идёт.
- `owner_names`: имена, которые никогда не должны попасть в коммит джобы.
- `git_name` / `git_email`: git-идентичность джобы; джоба не может её подменить.
- Ещё: `owner_rules_path`, `claude_bin`, `tmux_bin`; переменные окружения `AGENT_JOBS_HOME`, `AGENT_JOBS_AGENT`, `AGENT_JOBS_CLAUDE_BIN`, `AGENT_JOBS_TMUX_BIN`.

**Демон на Linux (пользовательская служба systemd)**

```bash
scripts/install-linux.sh --instance my-agent              # сборка, юнит, init, enable + старт agent-jobs@my-agent
systemctl --user status agent-jobs@my-agent
journalctl --user -u agent-jobs@my-agent -f               # журнал демона
scripts/install-linux.sh --instance my-agent --uninstall
```

Без sudo, только для текущего пользователя, идемпотентно. В юните `KillMode=process`, поэтому перезапуск демона не убивает идущие джобы: следующий демон их подхватывает и собирает. Чтобы демон пережил выход из системы, включите lingering (`loginctl enable-linger $USER`).

**Демон на macOS (launchd)**

```bash
AGENT=my-agent BIN="$HOME/.local/bin/agent-jobs"
sed -e "s|{{AGENT}}|$AGENT|g" -e "s|{{BIN}}|$BIN|g" -e "s|{{HOME}}|$HOME|g" \
  launchd/com.agent-jobs.daemon.plist.template > ~/Library/LaunchAgents/com.agent-jobs.$AGENT.plist
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.agent-jobs.$AGENT.plist
```

**Использование (CLI)**

```bash
agent-jobs start --agent my-agent --title "review auth" --kind review \
  --repo ~/src/project --base main --complexity normal \
  --brief-file brief.md                 # сразу печатает id джобы
agent-jobs list   --agent my-agent
agent-jobs status --agent my-agent <id>
agent-jobs result --agent my-agent <id> # строка job-done + report.md
agent-jobs cancel --agent my-agent <id>
agent-jobs version                      # или --version
```

**Если джоба упала**, смотрите `~/.agent-jobs/<agent>/jobs/<id>/`: сначала `stderr.log`, потом `stream.jsonl`, `exit_code`, `report.md`.
