## В работе

**[PR #4](https://github.com/qwwiwi/agent-jobs/pull/4): MCP-тулы джоб.**

- Один MCP-сервер на Go для каждого агента в двух ролях: `orchestrator` (главная сессия) и `job`. Роль джобы — разрешённый перечень; скрытые тулы отклоняет сам сервер, а тест падает, если тул не попал ни в один список.
- `job_start`, `job_status`, `job_result`, `job_list`, `job_cancel` поверх существующего менеджера.
- `mcp.json` джобы указывает на сервер в роли джобы.
- Вызывающий обязан указать модель или сложность: классификатора нет, догадок нет.
- Поддержка сокета tmux для строки job-done.
- Гвард: джоба не может запускать другие джобы и управлять ими через CLI (метка в окружении; проверка цепочки родительских процессов добавляется в круге ревью).

**[PR #9](https://github.com/qwwiwi/agent-jobs/pull/9): prune, doctor procs, системные и файловые тулы.**

- `agent-jobs prune [--dry-run]`: у папок джоб, закончившихся больше 48 часов назад, остаются записи и маленькие текстовые файлы верхнего уровня; рабочие папки, кеши, сборки, бинарники, большие файлы и симлинки уходят.
- `agent-jobs doctor procs [--kill]`: процессы, пережившие свою джобу или сессию, и строки running с мёртвым pid; только отчёт, `--kill` завершает лишь процессы, доказанно принадлежащие закончившейся джобе (DEVIATIONS #13).
- Тулы оркестратора `system_doctor`, `system_logs`, `activity_report`, `trash_move`, `trash_restore` (джобе — ни одного).

## Волна A

- **Тулы памяти, задач и команды через общий мозг.** `memory_search`, `memory_write`, `memory_already_exists`; `task_create`, `task_list`, `task_update`, `task_get`; `send_message`, `inbox`. Имена как в эталоне, работают поверх общей памяти и задач команды (DEVIATIONS #2, #3). Джобе доступны только `memory_search` и `memory_write`.
- **Заметки памяти в брифе.** Демон добавляет в каждый бриф до шести самых близких заметок из общей памяти, чтобы джоба не переоткрывала уже записанное. Если память недоступна, джоба всё равно стартует, и бриф об этом говорит.

## Волна B

- **Продолжение.** `job_resume` и `agent-jobs resume <id>`: новая джоба с тем же брифом, старые коммиты и дифф переносятся из сохранённых патчей, а в начале брифа написано, что перенеслось и что нет.
- **Расписания.** `schedule_add`, `schedule_list`, `schedule_remove`. Cron-выражение в местном времени и промпт, проверка раз в минуту, доставка одним из двух способов:
  - в живую сессию сообщением с меткой (несколько наступивших сразу приходят одним сообщением: «это разные инструкции, сделай каждую»);
  - как джоба, если у расписания задан вид; тогда сессия видит только строку job-done.
  Расписание хранит модель и лимиты с момента создания. Пропущенное срабатывание теряется, а не ставится в очередь, поэтому окна проверок идут с нахлёстом. Строки расписаний не истекают: их правят на месте и удаляют только по решению владельца.
- **Сторож мёртвой руки.** Проверки, которые молчат, когда всё хорошо, оставляют отметку о завершении; сторож сравнивает отметки с расписанием.
- **Собственные цели.** `intention_add`, `intention_list`, `intention_set`.
- **`notify_owner`.** Сообщение владельцу через уже существующий канал агента (DEVIATIONS #4).
- **Ежедневная автоматика.** `prune` и `doctor procs` раз в сутки сами.
- **Раннер Codex.** Джоба может идти на `codex exec` вместо `claude -p` (DEVIATIONS #5); там нет потолков на ходы и бюджет, поэтому ограничитель — таймаут.

## Волна C

- **Индекс кода в виде графа.** Отдельный MCP-сервер из эталона, индексирующий код как граф; джобы могут читать и индексировать. Сначала исследование: выбрать или написать индексатор, потом встроить.

## Отложено

Запланировано, но каждое ждёт отдельного решения владельца:

- **Сердцебиение.** Демон решает, будить ли агента ради его собственных целей: дешёвая проверка на Go (время, дневной лимит, ночь), потом маленькая модель решает (DEVIATIONS #1).
- **Stop-хук «владелец ждёт».** Джоба, запущенная по просьбе владельца, помечается; пока оркестратор не написал владельцу, Stop-хук не даёт сессии закончить ход молча.
- **Запасная оплата через API.** Когда недельное окно подписки почти исчерпано, джобы могут идти на кредитах API, только с явным согласием и потолком.
- **HTTP API только на чтение** для панели джоб (DEVIATIONS #8).

## Сверка с эталоном после каждой волны

Перед слиянием волны эталон проходится построчно: для каждого утверждения — реализовано ли, где (`file:line`), один в один или по перечисленному отличию. Отличие, которого нет в [DEVIATIONS.md](DEVIATIONS.md), блокирует слияние. Таблица сверки публикуется вместе с волной.
