# Architecture (stage 1 core + stage 2 MCP job tools + prune, doctor, system and file tools)

Implements [`docs/REFERENCE.md`](REFERENCE.md), section «How to do it yourself (minimum)», items 1–6. Quotes in Russian below are from the original, [`docs/REFERENCE.ru.md`](REFERENCE.ru.md) (section «Как сделать у себя (минимум)»). Deviations are only those in `docs/DEVIATIONS.md` (#6 model by kind × complexity, #7 naming are used here).

**MCP tools.** The reference starts jobs with the MCP tool `job_start` and reads reports with `job_result`. `agent-jobs mcp --role orchestrator|job --agent A` is that server (stdio, `github.com/modelcontextprotocol/go-sdk`), built on the same Manager as the CLI (`agent-jobs start/status/result/list/cancel`, kept for manual use).

| tool | role | wraps |
|---|---|---|
| job_start | orchestrator | `Manager.Enqueue` – an explicit `model` or a `complexity` required (neither = rejected); limits default/ceiling as the CLI; returns the queued row |
| job_status | orchestrator | `Store.Get` |
| job_result | orchestrator | `Store.Get` + `DoneLine` + `report.md` (capped at 256 KB; opened with `O_NONBLOCK|O_NOFOLLOW` and read only if the opened fd is a regular file – a FIFO, symlink or directory planted by the job is reported as missing, never waited on) + paths of the patches/logs that exist (lstat, regular files only, never read) |
| job_list | orchestrator | `Store.List` / `Store.ListRecentByStatus`, newest first, limit 1..200 |
| job_cancel | orchestrator | `Manager.Cancel` (also gives up a `stopped` job) |
| job_stop | orchestrator | `Manager.Stop` – kill like cancel, status `stopped`, work dir and session kept |
| job_resume | orchestrator | `Manager.Resume` – next attempt of the same id in the same session (or the fallback), limits default to what is left |
| job_amend | orchestrator | `Manager.Amend` – append to a queued job's brief |
| system_doctor | orchestrator | `Manager.Disk` (statfs of the state dir + a prune dry run) + `Queue` + `DoctorProcs(false)` (never kills) + `Hooks` (the guard command from settings.json run through `sh -c` with a `git push` payload → must exit 2, `ls` → 0; owner rules readable and ≤ 8 KB; `tmux has-session` on the notify target) → `ok` and a problem list (disk ≥ 90 % used or < 2 GiB free, a failing hook, job ghosts, dead running rows) |
| system_logs | orchestrator | last 1..2000 lines (default 100) of `<state>/daemon.log` (launchd) or `journalctl --user --unit agent-jobs@<agent>.service` (systemd, DEVIATIONS #11); with `job_id` the job's `stderr.log`, opened `O_NOFOLLOW|O_NONBLOCK`, regular files only, last 1 MiB |
| activity_report | orchestrator | `Store.ListActivity`: jobs created or finished in the window (1..720 h, default 24) plus all queued/running, at most 1000; counts by status, cost/turns/time of the finished ones |
| trash_move, trash_restore | orchestrator | `internal/trash` on `<state>/trash`, roots from config `trash_roots` (no default: closed until set), the agent-jobs home, owner rules, binary, `~/.claude`, `$CLAUDE_CONFIG_DIR`, `~/.claude.json` and `.git` protected (see Trash) |

Audiences live in `internal/mcp/registry.go`: `OrchestratorOnly` and `JobAllowed` (an allow-list; empty until memory tools arrive). A test fails when a tool is in neither list or in both. The job-role server registers only `JobAllowed` tools **and** a receiving middleware refuses any other `tools/call` and filters `tools/list`, so the boundary holds even if a hidden tool were registered. The job role does not open the job database.

## Components

| component | where | what it does |
|---|---|---|
| store | `internal/store` | SQLite table `jobs` (modernc.org/sqlite, WAL, busy_timeout). Only `queued`/`running` rows can change status, except `job_resume` (`stopped`/`timeout`/`failed` → `queued`, the previous attempt archived in the `attempts` table) and the cancel of a `stopped` row. A tick claims a job (`queued → running` + random `launch_token`) before anything is spawned, and its terminal update is `WHERE status='running' AND launch_token=?` – a tick can never finish another tick's job. Only an explicit cancel or stop finishes by id alone. |
| manager | `internal/jobs` | enqueue (validation, defaults, ceilings), launch, collect, timeout, cancel, notify, cleanup. |
| wrapper | `agent-jobs run-wrapper` | holds `wrapper.lock` (a second wrapper for the job refuses); under `admit.lock` checks that the job row is still `running` with its launch token (otherwise exits 4: no claude, no exit_code) and registers itself in `wrapper.json` (pid, pgid, launch token); then runs claude with a scrubbed git environment (below) and prompt.md on stdin, writes stream.jsonl / stderr.log, extracts report.md, writes exit_code last. |
| guard | `internal/guard`, `agent-jobs guard` | PreToolUse hook (exit 2 = block, reason on stderr). |
| daemon | `agent-jobs daemon` / `tick` | one tick per minute; launchd template in `launchd/` (macOS), systemd user unit `deploy/systemd/agent-jobs@.service` + `scripts/install-linux.sh` (Linux, `KillMode=process`). |
| templates | `prompts/*.md`, `rules/owner.md` | embedded in the binary (`assets.go`). |

## State layout

`~/.agent-jobs/<agent>/` (override root with `AGENT_JOBS_HOME`):

- `jobs.db` – SQLite
- `config.json` – optional, see README
- `owner-rules.md` – owner rules (default path); the job profile when generated by `agent-jobs profile --from FILE...` (marked sections `<!-- agent-jobs:profile -->` … `<!-- /agent-jobs:profile -->` of the agent's own rules, ≤ 8 KB, a hand-written file replaced only with `--force`)
- `cards/<name>.md` – project cards (config `cards_dir`): front matter `repo:` (absolute top-level path) and/or `remote:` (identity `net:host/path` or `local:/abs/path`, see `RemoteIdentity`; control characters refused), then a body; the file is at most 4 KB, opened `openat(O_NOFOLLOW)` relative to the cards dir and read bounded from that descriptor (stack, check runner, do not touch, known traps). Read at prepare time; every card matching the job's repository (by path or by any remote) goes into the brief after the owner rules, ≤ 8 KB for the rendered section (headings included); an unreadable, unparsable or oversized card refuses the start of repository jobs. `agent-jobs card new --repo PATH` writes one from `cards/template.md`, `card list [--repo PATH]` shows them
- `subagents/<id>.log` – one line per subagent the guard allowed for job `<id>` (at most 3); outside the job dir
- `jobs/<id>/` – per job:

| file | what it is |
|---|---|
| prompt.md | assembled brief given to claude on stdin |
| settings.json | the job's only settings: deny rules and the guard hook |
| mcp.json | the job's MCP servers, and only those: `agent-jobs mcp --role job --agent <agent>` |
| gitconfig | the job's only global git config (`GIT_CONFIG_GLOBAL`): the identity from `git_name`/`git_email`, nothing else (read-only) |
| no-hooks/ | empty read-only dir; `core.hooksPath` points here, so repository hooks never run |
| work/ | working dir: git worktree (detached at base) or empty dir |
| base_commit | commit the worktree started from; diffs are measured from it |
| stream.jsonl | claude stream-json events |
| stderr.log | claude stderr (+ wrapper errors) – first place to look when a job fails without a report |
| wrapper.json | the wrapper's pid/pgid/launch token, written before claude starts (adoption after a daemon crash) |
| admit.lock | admission handshake: wrapper (check row + register), `cancel` and the launch-grace failure take it, so a late wrapper never runs claude for a terminal row |
| worktree.json | path, admin gitdir and base of the worktree this job created (ownership check before cleanup) |
| exit_code | written by the wrapper when claude exits (written last) |
| resume.md, fallback.md | stdin of a resumed attempt: the update (same session) / brief + previous attempt + update (fresh session) |
| fallback_session | the fresh session id when the wrapper fell back from a failed `--resume` |
| attempts/<n>/, report.attempt-<n>.md | run files and report of earlier attempts of a resumed job |
| report.md | the job's final message (`result` of the last stream `result` event; when that text is empty after a successful result and the job wrote no report.md, the last top-level assistant text starting with `## Summary`; after an idle-after-result close, see below) |
| closed_idle_after_result | written by the wrapper when it ended claude by the idle-after-result rule; one line, recorded as the job row's message. Belongs to one attempt: whatever runs claude again in the same job dir must move it aside with the attempt's other files |
| diffstat.txt, commits.patch, staged.patch, uncommitted.patch, untracked.tar | what the job changed; written right before the worktree is removed (when the repository config names filter/diff drivers: only `diffstat.txt` with the reason, worktree kept) |

`argv.txt`, `launches.txt` appear only in tests (the fake claude writes them). `<state>/tick.lock` is the per-agent lifecycle lock.

## Flows

**Start.** `agent-jobs start` validates kind, limits (defaults 80 turns / $10 / 45 min; above 200 / $50 / 180 → error, never clamped), resolves repo + base to a commit SHA, picks the model (explicit `--model`, validated as a model name so it can never become a flag; else the kind × complexity table; neither given = rejected, complexity is never defaulted), inserts a `queued` row and prints the id. Nothing runs yet.

**Tick** (every minute, also `agent-jobs tick`) runs under an exclusive `flock` on `<state>/tick.lock` (also taken by `cancel`), so two daemons or a manual tick never interleave. In this order:
1. *Collect* each `running` job. A claimed job without a recorded pid (daemon died between spawn and pid write) is adopted from `wrapper.json` if its token matches; with no `wrapper.json` after 1 minute it is `failed` under `admit.lock` ("the wrapper never registered", work dir kept). Then: `exit_code` present → stream.jsonl is read *after* it (so the result is complete) → verdict; else past `started_at + timeout` → SIGTERM to the process group, 10 s, SIGKILL → `timeout`; else wrapper PID dead → re-check exit_code, then `failed` ("wrapper died without writing exit_code").
2. *Launch* queued jobs while fewer than 2 are running. Launch = claim (`running` + token) → prepare job dir (owner rules must be readable and ≤ 8 KB, else the job is `failed` with "refused to start: …") → start `agent-jobs run-wrapper <jobdir> --token T -- claude <args>` with `Setsid` (own session → own process group, not a child of the daemon's group) → store PID = PGID.
3. *Notify* finished, not yet notified jobs: `tmux send-keys -t <target> -l "<line>"`, then `tmux send-keys -t <target> Enter` (both with `-L <tmux_socket>` when configured). The line is printable-only (whitespace → space, control/format characters such as Ctrl-U, ESC, bidi overrides dropped; title capped at 120 runes), so a title cannot type keystrokes into the session. With a target configured, a job is marked notified only after tmux accepted the line: a failing tmux (missing session) keeps it pending, logged and retried next tick, and cleanup waits. With no target configured notify is off: the line goes to the daemon log and the job is marked notified at once, so the 30-minute cleanup still runs.
4. *Cleanup* jobs notified ≥ 30 min ago (see below).

**Idle after result.** `claude -p` can stay alive after its final `result` event (seen with background subagents: every result was printed, then the process idled with only the job's MCP server as a child) and would otherwise run into the timeout. While claude runs, the wrapper follows stream.jsonl. When the last event is a `result`, the last `background_tasks_changed` event lists no task, and for the whole grace period (`idle_after_result_seconds`, default 180) nothing new arrived and claude had no live descendant other than the job MCP server (this binary running `mcp --role job`, from `/proc`; a live child restarts the grace), the wrapper sends claude SIGTERM, then SIGKILL after 10 s (as cancel does). It then settles report.md, in this order: the last `result` text if it starts with `## Summary`; else a report.md the job wrote itself, left untouched; else the last top-level assistant text (no `parent_tool_use_id`, so no subagent output) that starts with `## Summary`; else a short note that the job ended without a report, writes `closed_idle_after_result` and sets exit_code by the last result: 0 when its subtype is `success`, not an error, and a report was found; 1 otherwise. The session sweep and the rest of the wrapper run as after a normal exit. The verdict records «closed by the idle-after-result rule (…)» in the job row; turns and cost come from the last `result` event. `idle_after_result_seconds: -1` turns the rule off. Linux only; elsewhere the rule is off.

**Verdict.** exit_code ≠ 0 → failed; stream `result.is_error` (e.g. max turns / budget) → failed; exit 0 but empty/missing report.md → failed ("exit 0 without a report"); otherwise succeeded. Turns and cost come from the stream `result` event; duration is wall time from start to collection.

**Daemon restart.** The wrapper lives in its own session and writes `exit_code` itself; the daemon keeps no in-memory state. Killing the daemon (even SIGKILL) leaves the job running; the next daemon/tick finds `exit_code` and collects it (tested with the real binary).

**Cancel** (under the lifecycle lock and the job's `admit.lock`). `queued` → `cancelled`; `running` → TERM group / 10 s / KILL → `cancelled`; `stopped` → `cancelled` (turns/cost of the stop kept; notify and cleanup then run as for any finished job). Other terminal jobs cannot be cancelled.

**States** (Wave E2, DEVIATIONS #14):

```
queued    ──tick claims──────────►  running      (attempt + 1)
queued    ──job_amend────────────►  queued       (attempt 0: brief += update; a queued resume: update += text; position kept)
queued    ──job_stop─────────────►  stopped      (attempt 0: no session yet; a queued resume keeps its update)
queued    ──job_cancel───────────►  cancelled
running   ──exit_code + verdict──►  succeeded | failed
running   ──past timeout─────────►  timeout
running   ──job_stop─────────────►  stopped      (work dir + session kept, not notified, not cleaned)
running   ──job_cancel───────────►  cancelled
stopped   ──job_resume───────────►  queued       (next attempt of the same id)
timeout   ──job_resume───────────►  queued       (next attempt of the same id)
failed    ──job_resume───────────►  queued       (next attempt of the same id)
stopped   ──job_cancel───────────►  cancelled    (then notified and cleaned up)
succeeded, cancelled: final
```

**Stop** (`job_stop` / `agent-jobs stop`, under the lifecycle lock and `admit.lock`). `queued` → `stopped` (attempt 0, no session yet). `running` → the process group is killed exactly as for cancel; the turns come from the stream's `result` event or, when the job was killed before it, from the number of distinct assistant messages in `stream.jsonl` (cost then unknown, said in the error field); the row ends `stopped` with the reason, and the attempt's cost is marked unknown (`cost_unknown`: a resume counts it at its whole budget). Then, the row no longer running, the job's processes that left its process group are swept as `doctor procs --kill` does for this job only (marker or the job's session): killed, or, when one leads its own session (`setsid`, may host other work), left running and named in the error field, as is "not checked" without Linux `/proc`; cancel does the same. The digest of the session transcript is recorded (as at every attempt's end). A job whose `exit_code` already exists is collected with its real verdict instead (the stop is refused). A stopped job is not notified and not cleaned up (PendingNotify / PendingCleanup skip it; prune skips it): its worktree, uncommitted files and session stay until it is resumed or cancelled.

**Resume** (`job_resume` / `agent-jobs resume`, under the lifecycle lock). Only `stopped`, `timeout` and `failed`; a job that never prepared its folder (refused to start) is refused. The same job id runs its next attempt: `Store.Requeue` archives the current attempt into the `attempts` table (number, mode, status, model, limits, usage, error, context, session id, times), resets the run fields (pid, token, finished/notified/cleaned, usage, error) and queues the row again with the new limits and the update (`pending_context`); `created_at` is kept, so the job keeps its original queue position. Limits: each one given explicitly or what the previous attempt left of its own (turns − used, budget − cost, minutes − elapsed); an attempt that ended without a `result` event (killed, stopped) has an unknown cost and counts at its whole budget, so the default budget is then nothing and `max_budget_usd` must be given. All attempts together stay within the ceilings: the new limit plus what earlier attempts used (unknown costs at their budgets) must fit, never clamped; nothing left and nothing given is an error. A job stopped while queued (attempt 0) gets the update appended to its brief and starts as a first attempt; a resume stopped while still queued (never ran, not archived again) keeps its update and gets the new one appended. Refused, here and again at launch: a `.claude` in the job dir, a `work/.claude` in a job without a repository, or a `work/.claude` that differs from the base commit (changed, staged, untracked or ignored files): claude loads settings, local settings, hooks, skills and agents from it at start, outside the guard, and the job (or another job) could have written it. `settings.json` also pins `disableAllHooks: false` (`--settings` outranks project settings). Same id, not a new linked job: claude finds a session by the cwd's project directory, so the attempt must run in the same `<jobdir>/work`, which belongs to the job id. On launch (`Claim` counts `attempt`), `prepareResume`: moves the previous run files to `attempts/<n>/` and its report to `report.attempt-<n>.md` (prune keeps small top-level text files), rewrites `settings.json`, `mcp.json`, `gitconfig`, `no-hooks/` from the config (the job dir is writable by the job; a filled `no-hooks/` refuses), restores the worktree if cleanup removed it (`git worktree add` at `refs/agent-jobs/jobs/<id>`, then `staged.patch` with `git apply --cached`, `uncommitted.patch` with `git apply`, `untracked.tar` extracted without `..`, absolute names or writes through symlinks; the owner mark re-written) and verifies it as cleanup does, then writes `resume.md` (the update: «Orchestrator update», the context, «Continue the task with this update; keep the report contract», the attempt's limits) and `fallback.md` (the prompt rebuilt from the database brief, owner rules and cards, plus «Previous attempt»: status, turns, error, its report or else its last assistant text, where its commits are, plus the update and «say so in Not done / uncertain»). If the session transcript is in the job's own project dir (`projects/<work dir, non-alphanumerics → '-'>/`; a long name is matched by its first 200 characters) and still has the SHA-256 recorded when the previous attempt ended (transcript plus its `<id>/` directory; another job can write `~/.claude/projects`), the wrapper runs `claude … --resume <session id>` with `resume.md` on stdin and `--fallback-prompt fallback.md --fallback-session <new id>`; if not (missing, or changed since), a fresh session (`--session-id <new id>`, stdin `fallback.md`, run mode `fallback`). The wrapper falls back by itself when a resume exits non-zero (not by a signal) before any `assistant` or `result` event: the failed stream is kept as `stream-resume-failed.jsonl`, `fallback_session` records the new id (the daemon validates it and stores it on the row when it collects), and claude runs once more in the fresh session. The job-done line of attempt N > 1 ends `· resumed (attempt N)` (`, fresh session` in fallback mode); `job_result` lists all attempts. The subagent cap stays per job (the counter is monotonic across attempts).

**Amend** (`job_amend` / `agent-jobs amend`, under the lifecycle lock): a queued first attempt gets `UPDATE … SET brief = brief || <update> WHERE status='queued'`; a queued resume (attempt > 0) gets the text appended to `pending_context`, which is what the resumed session (and a fallback) receives. The row's `created_at`/rowid, so its queue position, are unchanged. Any other status is refused.

**Sessions on disk.** Without `--no-session-persistence` claude keeps each job's transcript in `${CLAUDE_CONFIG_DIR:-~/.claude}/projects/<cwd with every non-alphanumeric character replaced by '-'>/<session id>.jsonl` plus a `<session id>/` directory (tool results, subagent transcripts); typically tens of KB to a few MB per job. `SessionPaths` finds them by the job's session id (glob over `projects/*/`, the id is a UUID the daemon generated), and `prune` removes them for the jobs it prunes (every attempt's session), never anything else in the claude config dir.

**Process-group kills** (timeout, cancel). `wrapper.json` lies in the job dir, which the job can write, so a pgid is never trusted: before any signal the daemon requires pgid > 1, pgid ≠ its own process group and `getpgid(wrapper pid) == pgid`; otherwise it refuses and logs (the row is still finished). Adoption from `wrapper.json` refuses a pgid ≤ 1, the daemon's own group, or a live pid that does not lead that group (the job then fails after the launch grace).

**Cleanup** (repo jobs only; empty work dirs are left for the future `prune`). First the ownership check: `<jobdir>/work` is a real directory (not a symlink), `worktree.json` path matches, the path is registered in `git worktree list --porcelain` of the source repo, its admin gitdir lies under `<repo common git dir>/worktrees/`, equals the one recorded at creation and carries this job's owner mark (`agent-jobs-owner`) – otherwise nothing is touched. Then the driver check: if the repository-level config (scopes `local` and `worktree`, includes followed; read with `git config --list --show-scope`) names a filter driver (`filter.*`), a diff driver command (`diff.*.command`) or a textconv (`diff.*.textconv`), any diff would run that program in the daemon, so no patch is made: `diffstat.txt` holds one line saying why, the worktree is kept for a human, the ref `refs/agent-jobs/jobs/<id>` is still set, the reason is logged and the job counts as cleaned (not retried). The daemon owner's global/system config (e.g. `filter.lfs`) does not count. Otherwise, without modifying the index or files: `diffstat.txt` = `git diff --stat <base>` + untracked list, `commits.patch` = `git format-patch <base>..HEAD --stdout`, `staged.patch` = `git diff --cached --binary HEAD`, `uncommitted.patch` = `git diff --binary HEAD`, `untracked.tar` = untracked, not ignored files (`git ls-files --others --exclude-standard`). Restore: in a fresh worktree checked out at `<base>`, with `J=<jobdir>` (empty patches are skipped – git rejects an empty patch; tested for only commits / only staged / only unstaged / only untracked / all / nothing):

<!-- restore -->
```sh
set -e
[ ! -s "$J/commits.patch" ] || git am "$J/commits.patch"
[ ! -s "$J/staged.patch" ] || git apply --cached "$J/staged.patch"
[ ! -s "$J/uncommitted.patch" ] || git apply "$J/uncommitted.patch"
tar -xf "$J/untracked.tar"
```

Then `git update-ref refs/agent-jobs/jobs/<id> <job HEAD>` in the source repo, then `git worktree remove --force <jobdir>/work` – only that path. Any failure before the removal keeps the worktree and retries next tick.

## Launch command (reference, except DEVIATIONS #14)

```
claude -p --output-format stream-json --verbose --model M \
  --max-turns N --max-budget-usd B \
  --permission-mode bypassPermissions \
  --settings <jobdir>/settings.json --setting-sources project \
  --mcp-config <jobdir>/mcp.json --strict-mcp-config \
  --add-dir <jobdir> --session-id <uuid> < prompt.md
```

The reference pins `--no-session-persistence`; here the session id is assigned before launch and stored on the row (`session_id`), so the job can be resumed: a resumed attempt replaces `--session-id <uuid>` with `--resume <uuid>` and reads `resume.md` instead of `prompt.md` (see Resume).

cwd = `<jobdir>/work`. Checked against claude 2.1.301: all flags accepted; `--max-turns` is not listed in `claude --help` but is accepted (real smoke run finished normally with it).

**Prune** (`agent-jobs prune [--dry-run]`, under the lifecycle lock). For every terminal job with `finished_at` older than 48 h: the job folder must be a real directory (else untouched); a repo job without `cleaned_at` is skipped (its patches are not saved yet). Each top-level entry is judged by `lstat`: the records `report.md`, `base_commit`, `diffstat.txt`, `commits.patch`, `staged.patch`, `uncommitted.patch`, `untracked.tar` always stay; other regular files stay when ≤ 1 MiB and text (no NUL, valid UTF-8 in the first 8 KiB, read `O_NOFOLLOW|O_NONBLOCK`); everything else goes – subdirectories (work dir, caches, builds, `no-hooks/`), binaries, large files, special files, symlinks (unlinked, never followed). Exception: `work/` of a repo job that still has a `.git` (the worktree cleanup kept for a human) stays. Removal never follows links (`os.RemoveAll`); read-only directories left by a job are made writable first (also the job folder itself). A second pass finds nothing.

**doctor procs** (`agent-jobs doctor procs [--kill]`, Linux `/proc`, processes of this uid, never this process or its ancestors). *Job ghosts*: a process whose environment carries `AGENT_JOBS_JOB=<id>` of a job in this agent's store that is finished or whose wrapper is dead (an id the store does not know – another agent's job – is not judged); or a process whose session id is the recorded pgid of a finished job and whose session leader no longer exists (a running row whose wrapper died is matched by marker only: its window has no end, so a later session reusing the id would match). Either way the process must have started inside the job's run window `[StartedAt-1s, FinishedAt+1s]` (start time from `/proc/<pid>/stat` + `btime`; no upper bound for a running row whose wrapper died), and a job that started before the current boot owns nothing. For a session the earliest-started live member of the session (any uid: the kernel keeps a session id allocated while any member lives) must be inside the window too, so a reused session id whose first member predates or postdates the job is not the job's. *Leaders*: a marked process inside the window that leads its own session (`sid == pid`, it daemonized – a tmux server whose environment, and every later pane, carries the marker); also a marked process whose session leader is alive and is not the job's recorded pgid, or that has a marked `sid == pid` ancestor other than the job's wrapper (it runs under such a daemon, e.g. in a tmux pane); reported, never killed. *Suspects*: a process whose session leader is gone and whose command line is a browser (chrome, chromium, headless_shell, playwright, firefox, …), a preview server (vite, next dev, http.server, serve, storybook, `npm run dev`, …) or a shell wait loop (`while`/`until` with `sleep`/`pgrep`/`kill -0`). *Dead rows*: running rows whose wrapper pid is dead, or claimed rows that never registered a wrapper after the launch grace. Report only; `--kill` signals job ghosts only, never leaders or suspects (DEVIATIONS #13): a pidfd is opened first, the start time and session are re-read and must equal the scanned ones, then SIGTERM, 3 s, SIGKILL through the descriptor; a changed identity or no pidfd = not signalled.

**Trash** (`internal/trash`). `trash_move` takes an absolute path without `..`, resolves its parent (`EvalSymlinks`) and requires the result strictly inside a resolved root – not a root, not an ancestor of a root, no `.git` component, not inside, equal to or containing a protected path. With no roots configured nothing is moved (fail closed; the tool says how to set `trash_roots`). Protected, whatever the roots: the agent-jobs home (every agent's state dir and job database, also the trash), the owner rules file, the agent-jobs binary (`SelfBin`, which the guard hook runs, and `os.Executable`), `~/.claude`, `$CLAUDE_CONFIG_DIR` when absolute, `~/.claude.json`. Each protected path counts as named (parent resolved, so a symlink is protected as the link) and fully resolved, and a symlink whose target resolves to a protected path is refused too. The last component is not followed (a symlink is moved as the link). It writes `<trash>/<id>/meta.json` (id, original path, time, type, size) first, opens the resolved parent and the entry dir `O_PATH|O_DIRECTORY|O_NOFOLLOW` and checks each descriptor's `/proc/self/fd` path, then `renameat2(…, RENAME_NOREPLACE)` moves the item to `<trash>/<id>/item`. Another filesystem (`EXDEV`) is refused, never copied. `trash_restore` re-runs the same checks on the original path, refuses an occupied path or a missing parent, and renames back with `RENAME_NOREPLACE`; an unknown id lists the 20 most recent entries. Trash entries are not expired automatically. macOS: the descriptors are opened `O_RDONLY|O_DIRECTORY|O_NOFOLLOW` and checked by fstat device/inode against an lstat of the directory (no `/proc/self/fd`; a swapped intermediate component is not detected there), the rename is `renameatx_np(…, RENAME_EXCL)`, and the `.git` and protected-path comparisons are case-folded (APFS is case-insensitive by default).

## Rules enforcement

What this is and is not: the deny rules and the guard block the *direct spellings* of outward actions in a Bash call, and the wrapper's git environment scrub keeps git itself from running programs the guard does not see. This is **not a sandbox**: a script the job writes and then runs is allowed by design (as in the reference), and what it does is not inspected. Within a single Bash call the guard rejects forms it cannot resolve statically around git/gh instead of guessing.

- **settings.json deny** (holds under bypassPermissions): `git push`, `git tag`, `git send-pack`, `git http-push`, attached forms `git -c*`, `git --config-env*`, `git --exec-path*`, `env -S*`, `env --split-string*`, `gh release`, `gh api`, `gh pr create|new|comment|edit|merge|review`, `gh issue create|new|comment|edit`, nested agents `claude`, `codex`, `gemini`, `aider`, `cursor-agent`, `claude-code`, `gemini-cli`, `aider-chat`, package runners `npx`, `pnpx`, `bunx`, `uvx`, `npm exec`, `pnpm dlx`, `yarn dlx`, `bun x`, `pipx run`, `uv tool run`, file tools inside `.git` (`Edit|Write|MultiEdit|NotebookEdit(**/.git/**)`), plus `CronCreate`, `RemoteTrigger`, `PushNotification` (tools that reach a human or outlive the run). `WebFetch`/`WebSearch` denied unless kind = research.
- **Guard hook** (PreToolUse, matcher `*`, inspects Bash and the file tools Write/Edit/MultiEdit/NotebookEdit; for a file tool it rejects a `file_path`/`notebook_path` inside a `.git` directory – checked as given (made absolute against the hook's `cwd`, cleaned, case-insensitive `.git` segment, git config/hooks/`$GIT_DIR` paths) and with symlinks resolved on the longest existing prefix (a dangling link is followed by its target), so a link in the job dir pointing into `.git` is caught; a path with a `..` segment is rejected outright (the kernel resolves `link/..` after the symlink, while cleaning drops it lexically); paths inside the job worktree's real git dirs (admin dir and common dir, from `git rev-parse` at prepare time, passed to the guard as `--git-dir` – `settings.json` is written after the worktree exists) are rejected whatever they are named). Prefix deny rules miss spellings, so the guard *parses* each command: quotes removed, split on `;` `&&` `||` `|` `&` newlines and parentheses, comments and here-doc bodies skipped, env prefixes and wrappers (`env`, `command`, `exec`, `nohup`, `timeout`, `xargs`, `sudo`, …) stripped, `$(…)`/backticks/`<(…)`, `sh|bash|zsh -c '…'` and `eval` parsed as nested scripts. Around git/gh, a form it cannot resolve statically is rejected with «guard cannot verify this form; write it as a plain command» – git/gh inside `$(…)`, backticks, `<(…)`, an unquoted here-doc body, `eval` or `sh -c`; stdin redirect, here-doc or here-string into git/gh (commit messages go through `-m '…'`, `-m "$(cat <<'EOF' … EOF)"` or `-F <file>`; `-F -`/`/dev/stdin` rejected); a command name, git subcommand, gh subcommand, `-c` value or commit message from a variable/substitution; a glob/brace character (`{ [ ? *`) in any word that decides which program runs – the command name, wrapper names and their option values, the `timeout` duration (`{git,push}`, `/usr/bin/g[i]t`, `timeout {5,git} push`; leading keywords, shell assignments and `[`/`[[` exempt) – or in a git global option or subcommand or a gh subcommand; `eval`/`sh -c` of a variable; a shell reading commands from stdin (`… | sh`, `bash <<EOF`); `env -S`; `xargs git`; attached `-cKEY=V`, `-C.`, `--config-env`, `--exec-path`; `alias` mentioning git/gh; any non-reader program (`find -exec`, `flock`, `trap`, `python -c`, `node -e`, `npx`, …) with git/gh (also `git-<sub>`), a shell or an agent among its arguments – as a whole word, a path base name, or a word inside an argument (`python3 -c '…subprocess.run(["claude", …])'`, `node -e '…codex…'`, `npx @anthropic-ai/claude-code`, `node …/claude-code/cli.js`; words matched: `git`, `gh`, `sh`, `bash`, `zsh`, `dash`, `fish` bounded by characters other than letters, digits, `_`, `-` and a leading `.`; `claude`, `codex`, `gemini`, `aider`, `cursor-agent` also with a `-suffix` (`claude-code`, `gemini-cli`, `aider-chat`, `@google/gemini-cli`, `@openai/codex`)) (readers such as `echo`, `grep`, `cat`, `which` are exempt); `cp`/`mv`/`install`/`ln` with git, gh, `git-<sub>`, a shell or an agent as an argument (a renamed executable; also via `$(which git)`). Program names are compared case-insensitively. It also rejects:
  - *nothing outside*: `git [global opts: -C, -c, --git-dir, …] push|tag|send-pack|http-push|send-email|imap-send|svn|p4|daemon|request-pull|instaweb|…` in any spelling (`git 'push'`, `/usr/bin/git push`, `/usr/lib/git-core/git-push` – any `git-<sub>` binary is read as `git <sub>`);

All long options are matched with git's abbreviations (`--ex`, `--templ`, `--strat`);

  - a `while`/`until` loop (also nested after `then`/`do`/`{`/`(`) with `pgrep -f`/`--full` whose pattern (as a regexp) matches the command's own text (`[s]erver` passes);
  - owner names (config `owner_names`) in the actual commit message: `-m`/`--message`/`-am`, `-F`/`--file` (file read relative to the hook's `cwd`; unreadable → block; stdin → block), `--trailer`, `--author`;
  - *git config that runs programs*: `git -c KEY` and `git config [set|--add|--file …] KEY VALUE` only for an allowlist of harmless keys (`user.name`, `user.email`, `commit.gpgsign`, `commit.verbose`, `color.ui`, `diff.renames`, `merge.conflictstyle`, … – see `gitConfigSafe`); everything else is rejected (`core.hooksPath`, `core.pager`, `core.editor`, `core.sshCommand`, `core.fsmonitor`, `credential.*`, `diff.external`, `*.textconv`, `filter.*`, `alias.*`, `include.*`, `url.*`, …), as is `git config --rename-section`; `git clone -c`/`--config` values (also `--conf=`, attached `-cKEY=V`, in a short cluster) go through the same allowlist, identity keys only with the configured value;

  - *package runners*: `npx`, `pnpx`, `bunx`, `uvx`, `npm exec|x`, `pnpm dlx`, `yarn dlx`, `bun x`, `pipx run`, `uv tool run` (subcommand looked for among the first three positional words), also as an argument of another program (`timeout 60 npx`, `find -exec npx`) – what runs is decided by a registry, and a job has no need for them;

Not resolved (residual gap, DEVIATIONS #12): other variables and substitutions in a path, file lists `xargs` reads from a file, and scripts the job writes. A subagent runs inside the job's claude process, so its tool calls hit the same deny rules and guard, and it inherits the job marker.

- **Job marker** (wrapper, before claude starts): any inherited `AGENT_JOBS_JOB` is dropped and `AGENT_JOBS_JOB=<job id>` is set on claude, so every process of the job carries it (also the marker doctor procs will use). Under the marker the binary refuses every command except `mcp --role job`, `guard`, `run-wrapper` and help (start, cancel, status, list, result, tick, daemon, init, `mcp --role orchestrator`, …: «refused: running inside job»), and `mcp.Serve` refuses the orchestrator role on its own. The marker is an environment variable, so a job *can* remove it in a script it writes (the guard is not a sandbox); the guard rejects the direct spellings (`unset`, `env -u`, assignments, `mapfile`). Two process-based checks therefore back it up for the same control commands: (1) the ppid chain is walked through `/proc` (at most 256 steps) and the command is refused if an ancestor's argv is the wrapper's (`<bin> run-wrapper <jobdir> --token …`, matched by structure, or an `agent-jobs*` script run by an interpreter); (2) the command is refused if its session leader (`getsid(0)`, read from `/proc/<sid>/cmdline`) has the wrapper's argv shape: the wrapper starts with setsid, so it leads the session of every job process that did not call setsid itself – also of an orphan re-parented away from the wrapper – and this check does not depend on the agent or state dir the command targets; (3) as a fallback when the leader has exited, once the agent's store is open, the command is refused if its session id equals the recorded pgid of one of that agent's running jobs. Checks (1) and (2) are Linux-only and **fail open** when `/proc` cannot be read (and on macOS, where they are skipped; the marker and check (3) still apply); a job process that both drops the marker and calls `setsid` (becoming its own session leader) is not caught – the guard rejects the direct spellings of that as well, but a script the job writes is not inspected. Together these close the direct ways a job could start, cancel or manage jobs.
- **Session sweep** (wrapper, after claude exits, before `exit_code`): nothing a job started may outlive it. The wrapper leads its own session (setsid), so on Linux it lists every live process whose session id is the wrapper's (from `/proc/<pid>/stat`, zombies skipped, the wrapper itself excluded) – also processes in other process groups and orphans re-parented away from it – sends them SIGTERM, waits up to 3 s, sends SIGKILL to whatever is left, and repeats (at most 5 rounds) until the session is empty; the count goes to `stderr.log`. Every signal goes through a pidfd: the descriptor is opened first (`pidfd_open`), session membership is checked only after it is open, and the signal is sent through it (`pidfd_send_signal`), so a pid reused by an unrelated process is never signalled. Without pidfd support (ENOSYS) nothing is signalled; there is no fallback to a bare `kill(pid)`. Fail closed: if processes are still alive after the last round, or the session cannot be enumerated or signalled, the wrapper still writes `exit_code` but first writes `sweep_incomplete` (survivor pids, then the error), and the daemon fails the job with «processes survived the job»; the job-done line ends with the same words. The daemon opens the marker without following links or blocking and reads it only as a regular file. Residual gap: the `/proc` enumeration is not atomic, so a process that forks between the directory read and the child's stat can leave a child that round did not see (the next round sees it, and one that keeps outpacing the rounds ends up as a survivor, failing the job); a survivor can also tamper with the job dir before the daemon reads it. The cgroup item in PLAN (Wave A) closes both. Only then is `exit_code` written, so a job is never reported finished while one of its processes can still act (e.g. a markerless orphan waiting for the session leader to go and then starting a job for another agent). This is also the reference's ghost-process cleanup for preview servers, browsers and wait loops a job forgot. Outside Linux the wrapper sends SIGTERM to its process group only (it ignores SIGTERM itself meanwhile). A process that called `setsid` itself has left the session and is not swept (DEVIATIONS #9, residual gaps).
- **Git environment scrub** (wrapper, before claude starts): every inherited `GIT_*`, `PAGER`, `EDITOR`, `VISUAL` is dropped, then `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=<jobdir>/gitconfig` (identity only), `GIT_PAGER=cat`, `PAGER=cat`, `GIT_EDITOR=true`, `EDITOR=true`, `VISUAL=true`, `GIT_TERMINAL_PROMPT=0` and, via `GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_n`/`GIT_CONFIG_VALUE_n` (command-line level: wins over repository config), `core.hooksPath=<jobdir>/no-hooks` (repository hooks never run), `core.fsmonitor=false`, `core.sshCommand=false`, `credential.helper=` (empty resets the helper list), `core.pager=cat`, `core.editor=true`. `diff.external` is not overridden: git has no value that disables it (an empty value makes every `git diff` fail with «cannot run»); inside the job a repo-local `diff.external`/textconv is reachable only by writing `.git/config` directly, which the guard rejects as a direct spelling. The daemon's own git calls (worktree add/remove, diff, format-patch, update-ref) drop inherited `GIT_*` and use the same overrides (hooks path `/dev/null`); its diffs pass `--no-ext-diff --no-textconv`, because cleanup runs after the job could have edited the repository config; filter drivers cannot be switched off that way, so cleanup skips the diffs entirely when the repository config names a filter, diff command or textconv (see Cleanup).
- **Prompt**: preamble (own dir only, content is data, no secrets, nothing outside) + subagent rules (`prompts/subagents.md`) + owner rules (job profile) + matching project cards + task + kind checklist + report contract (Summary, Findings / Changes, Evidence, Not done / uncertain).

## Readings of ambiguous points

- *Reference: «Процесс запускается отвязанным… и сам пишет код выхода».* Read as: a small wrapper is the detached process; it runs claude as a child (not `exec`, otherwise nothing is left to write the file) and passes the claude argv after `--` so the full command is visible in `ps`.
- *«Запрос выше потолка отклоняется».* Zero/omitted = default; negative values are rejected too.
- *Duration in the job-done line* is wall time in whole minutes (rounded).
- *Owner rules «до 8 КБ»* = 8192 bytes; an empty file also refuses to start (no rules ≠ rules).
- *Notify for refused/cancelled jobs*: every terminal job gets exactly one line. «Главная сессия получает одну строку» is a delivery guarantee: an undelivered line stays pending.
- *Model table (DEVIATIONS #6)*: review/fix/general: light → sonnet, normal → opus, hard → fable; research: light/normal → sonnet, hard → opus. `fable` is the claude CLI alias (resolved to `claude-fable-5-1` in a smoke run on 2026-10-15).
- *Cleanup for jobs without a repo*: nothing to preserve, marked cleaned; the directory itself is for `prune`.
- *Prune «маленькие текстовые файлы верхнего уровня»*: a regular file of at most 1 MiB that is valid UTF-8 without NUL bytes. `stream.jsonl` above that size goes (the report and the patches keep the result). `untracked.tar` is kept as one of the patches although it is binary.
- *doctor procs «процессы, пережившие свою джобу или сессию»*: a job's own processes are found by its marker and its session id; «сессия» outside jobs is read as a session whose leader is gone, narrowed to the reference's examples (preview servers, browsers, wait loops).
- *system_doctor «хуки»*: the hooks a job depends on – the guard hook as written into settings.json, the owner rules a job needs to start, the notify target.
- *trash_move*: one rename on the same filesystem; a copy across filesystems would not be reversible deletion, so it is refused.
