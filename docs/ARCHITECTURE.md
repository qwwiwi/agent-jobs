# Architecture (stage 1 core + stage 2 MCP job tools + prune, doctor, system and file tools + shared-brain tools + cgroup containment)

Implements [`docs/REFERENCE.md`](REFERENCE.md), section «How to do it yourself (minimum)», items 1–6. Quotes in Russian below are from the original, [`docs/REFERENCE.ru.md`](REFERENCE.ru.md) (section «Как сделать у себя (минимум)»). Deviations are only those in `docs/DEVIATIONS.md` (#6 model by kind × complexity, #7 naming are used here).

**MCP tools.** The reference starts jobs with the MCP tool `job_start` and reads reports with `job_result`. `agent-jobs mcp --role orchestrator|job --agent A` is that server (stdio, `github.com/modelcontextprotocol/go-sdk`), built on the same Manager as the CLI (`agent-jobs start/status/result/list/cancel`, kept for manual use).

| tool | role | wraps |
|---|---|---|
| job_start | orchestrator | `Manager.Enqueue` – an explicit `model` or a `complexity` required (neither = rejected); limits default/ceiling as the CLI; returns the queued row |
| job_status | orchestrator | `Store.Get` |
| job_result | orchestrator | `Store.Get` + `DoneLine` + `report.md` (capped at 256 KB; opened with `O_NONBLOCK|O_NOFOLLOW` and read only if the opened fd is a regular file – a FIFO, symlink or directory planted by the job is reported as missing, never waited on) + paths of the patches/logs that exist (lstat, regular files only, never read) |
| job_list | orchestrator | `Store.List` / `Store.ListRecentByStatus`, newest first, limit 1..200 |
| job_cancel | orchestrator | `Manager.Cancel` |
| job_stats | orchestrator | `Manager.Stats` over `Store.ListStats` (rows finished at or after `since`: `<n>d`, a Go duration or `YYYY-MM-DD`), grouped `by` kind \| model \| skill; same JSON as `agent-jobs stats --json` |
| system_doctor | orchestrator | `Manager.Disk` (statfs of the state dir + a prune dry run) + `Queue` + `DoctorProcs(false)` (never kills) + `Hooks` (the guard command from settings.json run through `sh -c` with a `git push` payload → must exit 2, `ls` → 0; owner rules readable and ≤ 8 KB; `tmux has-session` on the notify target) → `ok` and a problem list (disk ≥ 90 % used or < 2 GiB free, a failing hook, job ghosts, dead running rows) |

Audiences live in `internal/mcp/registry.go`: `OrchestratorOnly` and `JobAllowed` (an allow-list: `memory_search`, `memory_write`). A test fails when a tool is in neither list or in both. The job-role server registers only `JobAllowed` tools **and** a receiving middleware refuses any other `tools/call` and filters `tools/list`, so the boundary holds even if a hidden tool were registered. The job role does not open the job database.

## Components

| component | where | what it does |
|---|---|---|
| store | `internal/store` | SQLite tables `jobs` and `job_stats` (one summary row per finished job, see Job stats) (modernc.org/sqlite, WAL, busy_timeout). Only `queued`/`running` rows can change status. A tick claims a job (`queued → running` + random `launch_token`) before anything is spawned, and its terminal update is `WHERE status='running' AND launch_token=?` – a tick can never finish another tick's job. Only an explicit cancel finishes by id alone. |
| manager | `internal/jobs` | enqueue (validation, defaults, ceilings), launch, collect, timeout, cancel, notify, cleanup. |
| wrapper | `agent-jobs run-wrapper` | holds `wrapper.lock` (a second wrapper for the job refuses); under `admit.lock` checks that the job row is still `running` with its launch token (otherwise exits 4: no claude, no exit_code) and registers itself in `wrapper.json` (pid, pgid, launch token); then runs claude with a scrubbed git environment (below) and prompt.md on stdin, writes stream.jsonl / stderr.log, extracts report.md, writes exit_code last. |
| guard | `internal/guard`, `agent-jobs guard` | PreToolUse hook (exit 2 = block, reason on stderr). |
| daemon | `agent-jobs daemon` / `tick` | one tick per minute; launchd template in `launchd/` (macOS), systemd user unit `deploy/systemd/agent-jobs@.service` + `scripts/install-linux.sh` (Linux, `KillMode=process`); on Linux each wrapper runs in its own transient scope `agent-jobs-<agent>-<id>.scope` (see «Cgroup containment»). |
| brain | `internal/brain` | the shared brain (DEVIATIONS #2, #3). `Brain` interface; `Client` calls the brain's MCP servers over streamable HTTP (one short session per call: connect, one tool call, close; bounded by `timeout_seconds`); `Disabled` (no `brain` block) fails every call with `ErrNotConfigured`; `Fake` is the in-memory brain of the tests. `SocketClient` is the job role's brain: `memory_search` / `memory_write` as one JSON request per connection to `<state>/brain.sock`, everything else refused. The daemon serves that socket (`Manager.ServeBrain`, mode 600, at most 8 calls at once; a stale socket is replaced, a live one or a non-socket file is left alone): only for a running job of the agent, only search and write. The job role reads no token and refuses to start without `AGENT_JOBS_JOB`. The HTTP client follows no redirect; its transport sets `Authorization` only for the configured endpoint's scheme and host. `task_update` is two calls: a status change that fails after the fields were set returns «fields updated, but the status change … failed». |
| templates | `prompts/*.md`, `rules/owner.md` | embedded in the binary (`assets.go`). |

## State layout

`~/.agent-jobs/<agent>/` (override root with `AGENT_JOBS_HOME`):

- `jobs.db` – SQLite
- `config.json` – optional, see README
- `owner-rules.md` – owner rules (default path); the job profile when generated by `agent-jobs profile --from FILE...` (marked sections `<!-- agent-jobs:profile -->` … `<!-- /agent-jobs:profile -->` of the agent's own rules, ≤ 8 KB, a hand-written file replaced only with `--force`)
- `cards/<name>.md` – project cards (config `cards_dir`): front matter `repo:` (absolute top-level path) and/or `remote:` (identity `net:host/path` or `local:/abs/path`, see `RemoteIdentity`; control characters refused), then a body; the file is at most 4 KB, opened `openat(O_NOFOLLOW)` relative to the cards dir and read bounded from that descriptor (stack, check runner, do not touch, known traps). Read at prepare time; every card matching the job's repository (by path or by any remote) goes into the brief after the owner rules, ≤ 8 KB for the rendered section (headings included); an unreadable, unparsable or oversized card refuses the start of repository jobs. `agent-jobs card new --repo PATH` writes one from `cards/template.md`, `card list [--repo PATH]` shows them
- the `brain` block of `config.json` – endpoints (`recall_url`, `memory_url`, `tasks_url`, `swarm_url`) and the token source (`token_file`, mode 600, or `token_env`); the token is read per call by the daemon and the orchestrator's MCP server (never by a job; `token_env` is dropped from the job's environment, also when the wrapper starts in its systemd scope: `systemd-run --scope` execs the wrapper with that scrubbed environment, a scope unit runs no process of its own, so the user manager's environment never reaches the job) and sent only as the `Authorization` header to the configured endpoint (README, «Shared brain», including the residual exposure: a job runs as the same user and can read a token file by itself)
- `subagents/<id>.log` – one line per subagent the guard allowed for job `<id>` (at most 3); outside the job dir
- `archive/<YYYY-MM>/<id>/` – the log archive (config `log_archive_dir`, default here; 0700): `stream.jsonl.gz`, `stderr.log.gz`, `prompt.md`, `report.md`, `diffstat.txt`, `meta.json` of a job prune cleaned; outside the job dirs, see Log archive
- `jobs/<id>/` – per job:

| file | what it is |
|---|---|
| prompt.md | assembled brief given to claude on stdin |
| settings.json | the job's only settings: deny rules and the guard hook |
| mcp.json | the job's MCP servers, and only those: `agent-jobs mcp --role job --agent <agent>` |
| gitconfig | the job's only global git config (`GIT_CONFIG_GLOBAL`): the identity from `git_name`/`git_email`, nothing else (read-only) |
| no-hooks/ | empty read-only dir; `core.hooksPath` points here, so repository hooks never run |
| work/ | working dir: git worktree (detached at base) or empty dir |
| base_commit | commit the worktree started from; diffs are measured from it |
| stream.jsonl | claude stream-json events |
| stderr.log | claude stderr (+ wrapper errors) – first place to look when a job fails without a report |
| wrapper.json | the wrapper's pid/pgid/launch token, written before claude starts (adoption after a daemon crash) |
| admit.lock | admission handshake: wrapper (check row + register), `cancel` and the launch-grace failure take it, so a late wrapper never runs claude for a terminal row |
| worktree.json | path, admin gitdir and base of the worktree this job created (ownership check before cleanup) |
| exit_code | written by the wrapper when claude exits (written last) |
| report.md | the job's final message (`result` of the last stream `result` event; when that text is empty after a successful result and the job wrote no report.md, the last top-level assistant text starting with `## Summary`; after an idle-after-result close, see below) |
| closed_idle_after_result | written by the wrapper when it ended claude by the idle-after-result rule; one line, recorded as the job row's message. Belongs to one attempt: whatever runs claude again in the same job dir must move it aside with the attempt's other files |
| diffstat.txt, commits.patch, staged.patch, uncommitted.patch, untracked.tar | what the job changed; written right before the worktree is removed (when the repository config names filter/diff drivers: only `diffstat.txt` with the reason, worktree kept) |

`argv.txt`, `launches.txt` appear only in tests (the fake claude writes them). `<state>/tick.lock` is the per-agent lifecycle lock.

## Flows

**Start.** `agent-jobs start` validates kind, limits (defaults 80 turns / $10 / 45 min; above 200 / $50 / 180 → error, never clamped), resolves repo + base to a commit SHA, picks the model (explicit `--model`, validated as a model name so it can never become a flag; else the kind × complexity table; neither given = rejected, complexity is never defaulted), inserts a `queued` row and prints the id. Nothing runs yet.

**Tick** (every minute, also `agent-jobs tick`) runs under an exclusive `flock` on `<state>/tick.lock` (also taken by `cancel`), so two daemons or a manual tick never interleave. In this order:
1. *Collect* each `running` job. A claimed job without a recorded pid (daemon died between spawn and pid write) is adopted from `wrapper.json` if its token matches; with no `wrapper.json` after 1 minute it is `failed` under `admit.lock` ("the wrapper never registered", work dir kept). Then: `exit_code` present → stream.jsonl is read *after* it (so the result is complete) → verdict; else past `started_at + timeout` → SIGTERM to the process group, 10 s, SIGKILL → `timeout`; else wrapper PID dead → re-check exit_code, then `failed` ("wrapper died without writing exit_code").
2. *Launch* queued jobs while fewer than 2 are running. Launch = claim (`running` + token) → prepare job dir (owner rules must be readable and ≤ 8 KB, else the job is `failed` with "refused to start: …") → decide the containment (Linux: probe a throwaway `systemd-run --user --scope`; see «Cgroup containment») and record the scope unit on the row → start `agent-jobs run-wrapper <jobdir> --token T -- claude <args>` with `Setsid` (own session → own process group, not a child of the daemon's group), through `systemd-run --user --scope --quiet --collect --unit=agent-jobs-<agent>-<id>.scope --property=TimeoutStopSec=<kill grace> --` when there is a scope (systemd-run execs the wrapper inside the new scope, same pid) → store PID = PGID.
3. *Notify* finished, not yet notified jobs: `tmux send-keys -t <target> -l "<line>"`, then `tmux send-keys -t <target> Enter` (both with `-L <tmux_socket>` when configured). The line is printable-only (whitespace → space, control/format characters such as Ctrl-U, ESC, bidi overrides dropped; title capped at 120 runes), so a title cannot type keystrokes into the session. With a target configured, a job is marked notified only after tmux accepted the line: a failing tmux (missing session) keeps it pending, logged and retried next tick, and cleanup waits. With no target configured notify is off: the line goes to the daemon log and the job is marked notified at once, so the 30-minute cleanup still runs.
4. *Cleanup* jobs notified ≥ 30 min ago (see below).

**Idle after result.** `claude -p` can stay alive after its final `result` event (seen with background subagents: every result was printed, then the process idled with only the job's MCP server as a child) and would otherwise run into the timeout. While claude runs, the wrapper follows stream.jsonl. When the last event is a `result`, the last `background_tasks_changed` event lists no task, and for the whole grace period (`idle_after_result_seconds`, default 180) nothing new arrived and claude had no live descendant other than the job MCP server (this binary running `mcp --role job`, from `/proc`; a live child restarts the grace), the wrapper sends claude SIGTERM, then SIGKILL after 10 s (as cancel does). It then settles report.md, in this order: the last `result` text if it starts with `## Summary`; else a report.md the job wrote itself, left untouched; else the last top-level assistant text (no `parent_tool_use_id`, so no subagent output) that starts with `## Summary`; else a short note that the job ended without a report, writes `closed_idle_after_result` and sets exit_code by the last result: 0 when its subtype is `success`, not an error, and a report was found; 1 otherwise. The session sweep and the rest of the wrapper run as after a normal exit. The verdict records «closed by the idle-after-result rule (…)» in the job row; turns and cost come from the last `result` event. `idle_after_result_seconds: -1` turns the rule off. Linux only; elsewhere the rule is off.

**Verdict.** exit_code ≠ 0 → failed; stream `result.is_error` (e.g. max turns / budget) → failed; exit 0 but empty/missing report.md → failed ("exit 0 without a report"); otherwise succeeded. Turns and cost come from the stream `result` event; duration is wall time from start to collection.

**Daemon restart.** The wrapper lives in its own session (and, on Linux with systemd, in its own scope under the user manager's `app.slice`, outside the daemon's service cgroup) and writes `exit_code` itself; the daemon keeps no in-memory state. Killing the daemon (even SIGKILL) leaves the job running; the next daemon/tick finds `exit_code` and collects it (tested with the real binary).

**Cancel** (under the lifecycle lock and the job's `admit.lock`). `queued` → `cancelled`; `running` → stop the job's scope, or without one TERM group / 10 s / KILL → `cancelled`. Terminal jobs cannot be cancelled.

**Scope stops** (timeout, cancel, and every time a scoped job's row turns terminal). `systemctl --user stop agent-jobs-<agent>-<id>.scope`: systemd sends SIGTERM to every process in the unit's cgroup, waits `TimeoutStopSec` (the kill grace, 10 s), sends SIGKILL and returns when the cgroup is empty; a unit already collected (the wrapper exited) is fine; a `failed` unit only when its cgroup is gone or empty. The unit name is recomputed from the agent and the job id, never read from the job dir. If systemctl cannot stop it (no user bus, the manager busy), the daemon sweeps the scope's cgroup itself (`/user.slice/user-<uid>.slice/user@<uid>.service/app.slice/<unit>`, the same pidfd rounds as the wrapper) and accepts the stop only when the cgroup is then gone or lists no live process. If that fails too, the stop is recorded as pending on the row (`scope_pending`) **before** the row turns terminal, the job is failed with «processes survived the job (scope not stopped, retried every tick: …)» (cancel keeps `cancelled`, timeout keeps `timeout`, with that note), timeout/cancel also fall back to the process-group kill below, and every tick retries the stop until the unit is gone; meanwhile the job-done line, `status`, `list` and `job_status` say «stop pending» and the worktree cleanup waits.

**Process-group kills** (timeout, cancel without a scope, or when the scope stop failed). `wrapper.json` lies in the job dir, which the job can write, so a pgid is never trusted: before any signal the daemon requires pgid > 1, pgid ≠ its own process group and `getpgid(wrapper pid) == pgid`; otherwise it refuses and logs (the row is still finished). Adoption from `wrapper.json` refuses a pgid ≤ 1, the daemon's own group, or a live pid that does not lead that group (the job then fails after the launch grace).

**Cleanup** (repo jobs only; empty work dirs are left for the future `prune`). First the ownership check: `<jobdir>/work` is a real directory (not a symlink), `worktree.json` path matches, the path is registered in `git worktree list --porcelain` of the source repo, its admin gitdir lies under `<repo common git dir>/worktrees/`, equals the one recorded at creation and carries this job's owner mark (`agent-jobs-owner`) – otherwise nothing is touched. Then the driver check: if the repository-level config (scopes `local` and `worktree`, includes followed; read with `git config --list --show-scope`) names a filter driver (`filter.*`), a diff driver command (`diff.*.command`) or a textconv (`diff.*.textconv`), any diff would run that program in the daemon, so no patch is made: `diffstat.txt` holds one line saying why, the worktree is kept for a human, the ref `refs/agent-jobs/jobs/<id>` is still set, the reason is logged and the job counts as cleaned (not retried). The daemon owner's global/system config (e.g. `filter.lfs`) does not count. Otherwise, without modifying the index or files: `diffstat.txt` = `git diff --stat <base>` + untracked list, `commits.patch` = `git format-patch <base>..HEAD --stdout`, `staged.patch` = `git diff --cached --binary HEAD`, `uncommitted.patch` = `git diff --binary HEAD`, `untracked.tar` = untracked, not ignored files (`git ls-files --others --exclude-standard`). Restore: in a fresh worktree checked out at `<base>`, with `J=<jobdir>` (empty patches are skipped – git rejects an empty patch; tested for only commits / only staged / only unstaged / only untracked / all / nothing):

<!-- restore -->
```sh
set -e
[ ! -s "$J/commits.patch" ] || git am "$J/commits.patch"
[ ! -s "$J/staged.patch" ] || git apply --cached "$J/staged.patch"
[ ! -s "$J/uncommitted.patch" ] || git apply "$J/uncommitted.patch"
tar -xf "$J/untracked.tar"
```

Then `git update-ref refs/agent-jobs/jobs/<id> <job HEAD>` in the source repo, then `git worktree remove --force <jobdir>/work` – only that path. Any failure before the removal keeps the worktree and retries next tick.

## Launch command (reference, 1:1)

```
claude -p --output-format stream-json --verbose --model M \
  --max-turns N --max-budget-usd B \
  --permission-mode bypassPermissions \
  --settings <jobdir>/settings.json --setting-sources project \
  --mcp-config <jobdir>/mcp.json --strict-mcp-config \
  --no-session-persistence --add-dir <jobdir> < prompt.md
```

cwd = `<jobdir>/work`. Checked against claude 2.1.301: all flags accepted; `--max-turns` is not listed in `claude --help` but is accepted (real smoke run finished normally with it).

**Prune** (`agent-jobs prune [--dry-run]`, under the lifecycle lock). For every terminal job with `finished_at` older than 48 h: the job folder must be a real directory (else untouched); a repo job without `cleaned_at` is skipped (its patches are not saved yet). Each top-level entry is judged by `lstat`: the records `report.md`, `base_commit`, `diffstat.txt`, `commits.patch`, `staged.patch`, `uncommitted.patch`, `untracked.tar` always stay; other regular files stay when ≤ 1 MiB and text (no NUL, valid UTF-8 in the first 8 KiB, read `O_NOFOLLOW|O_NONBLOCK`); everything else goes – subdirectories (work dir, caches, builds, `no-hooks/`), binaries, large files, special files, symlinks (unlinked, never followed). Exception: `work/` of a repo job that still has a `.git` (the worktree cleanup kept for a human) stays. Removal never follows links (`os.RemoveAll`); read-only directories left by a job are made writable first (also the job folder itself). Before the entries are judged, the job's records move into the log archive (below); if that fails (a symlinked archive path, a full disk) `stream.jsonl` and `stderr.log` stay, the rest of the folder is still judged and cleaned, and the error is reported. After the jobs, archived months past the retention are removed. A second pass finds nothing.

**Log archive** (`internal/jobs/archive.go`; part of every prune, alone as `agent-jobs archive [--dry-run] [--json]`, under the lifecycle lock). Same jobs as prune (terminal, finished > 48 h, real job folder, repo jobs only after cleanup). Destination `<archive>/<YYYY-MM>/<id>/`, the month being the UTC month of `finished_at`; `<archive>` = config `log_archive_dir` (absolute) or `<state>/archive`. The root, the month dir and the job dir are checked with `lstat`: a symlink is refused (never followed) and fails the job's archive; the root is created 0700 with a marker file `.agent-jobs-archive` and a root holding the marker is kept 0700 (the logs carry tool output). An existing root without the marker (a folder the owner already uses) is archived into but never chmodded or expired; prune and `agent-jobs archive` then print `retention off: no marker in <root>` (JSON `retention_off`) while `log_archive_days` > 0. The default root `<state>/archive` belongs to agent-jobs: a pass that writes gives it a missing marker back (one left without it by an earlier build or by a marker write that failed after the mkdir). When the archive of a job fails (a refused path, a full or missing disk), prune keeps `stream.jsonl`, `stderr.log` and the copied records (`prompt.md`, `report.md`, `diffstat.txt`), still cleans the rest of the folder and reports the error. Before the build, temporary dirs `.<id>.tmp-*` of this job left by an interrupted pass are removed. The archive is built in a temporary dir `.<id>.tmp-*` next to its destination and renamed into place, so a half-written archive is never taken for a finished one: `stream.jsonl` and `stderr.log` gzipped, `prompt.md`, `report.md`, `diffstat.txt` copied, `meta.json` = the job row without the launch token (the brief is in `prompt.md`). Sources are opened `O_NOFOLLOW|O_NONBLOCK` and copied only when the opened fd is a regular file; outputs (`meta.json` and the marker included) are created `O_EXCL|O_NOFOLLOW` 0600 and fsynced; the temporary dir is fsynced before the rename, the month dir and the root after it. After the rename the gzipped originals are removed from the job folder (`report.md`, `diffstat.txt`, `prompt.md` stay there as before). A job already archived is not archived again; leftover originals of an interrupted pass are removed only when the destination holds `meta.json` and the `.gz` copy of each of them (an emptied or partial destination keeps them and reports an error). The job folder is made 0700 first if the job made it read-only (also for `agent-jobs archive` alone). Retention (roots with the marker only): config `log_archive_days` (default 365, 0 = forever); a top-level `<YYYY-MM>` entry whose month ended more than that many days ago is removed (a symlink as a link); other entries are left alone. The archive lies outside `jobs/`, so cleaning job folders never touches it; an external backup of the state dir (a nightly restic or rsync of the home dir) carries it off the machine.

**Job stats** (`internal/jobs/stats.go`, table `job_stats`). One row per finished job, written right after the terminal status is recorded (collect, timeout, cancel, a refused launch; all under the lifecycle lock), and by prune before a job's stream moves to the archive if the row is still missing; a failed write is logged and left to `agent-jobs stats --backfill`. The wrapper is not involved. Columns: id, kind, model, status, turns, cost_usd, duration_sec (from the job row), created/started/finished, repo (basename only), tool_calls (JSON, by tool name; subagents' calls included), skills (JSON, by name: `Skill` tool calls and `Read`/`Glob`/`Grep` under a `skills/<name>/` dir), guard_refusals and guard_rules (JSON, by rule: an `is_error` tool result carrying a `blocked by guard:` / `agent-jobs guard:` message, mapped to a rule name by `guard.RuleName`), subagents (Agent/Task calls the guard did not refuse, at least the store's counter), has_report (non-empty `report.md` in the job folder or the archive), result_subtype (last `result` event), source (`job_dir`, `archive`, `none`). The stream is read from `<jobdir>/stream.jsonl` or `<archive>/<YYYY-MM>/<id>/stream.jsonl.gz` (both `O_NOFOLLOW`), streaming, a line at a time; lines over 8 MiB are skipped without being held. `agent-jobs stats --backfill [--all]` writes the missing rows (every row with `--all`) under the lifecycle lock. `agent-jobs stats [--since D] [--by kind|model|skill] [--json]` and the `job_stats` tool aggregate: totals and per-group jobs, counts by status, success rate (succeeded / jobs), cost total, median and p90, duration median and p90 (nearest rank), turns, refusals, subagents, jobs without a report; the top 20 guard rules and tools; skills by uses with the jobs that used them and their success rate. With `--by skill` a job counts in every skill it used, jobs without one under `(none)`.

**doctor procs** (`agent-jobs doctor procs [--kill]`, Linux `/proc`, processes of this uid, never this process or its ancestors). *Job ghosts*: a process whose environment carries `AGENT_JOBS_JOB=<id>` of a job in this agent's store that is finished or whose wrapper is dead (an id the store does not know – another agent's job – is not judged); or a process whose session id is the recorded pgid of a finished job and whose session leader no longer exists (a running row whose wrapper died is matched by marker only: its window has no end, so a later session reusing the id would match). Either way the process must have started inside the job's run window `[StartedAt-1s, FinishedAt+1s]` (start time from `/proc/<pid>/stat` + `btime`; no upper bound for a running row whose wrapper died), and a job that started before the current boot owns nothing. For a session the earliest-started live member of the session (any uid: the kernel keeps a session id allocated while any member lives) must be inside the window too, so a reused session id whose first member predates or postdates the job is not the job's. *Leaders*: a marked process inside the window that leads its own session (`sid == pid`, it daemonized – a tmux server whose environment, and every later pane, carries the marker); also a marked process whose session leader is alive and is not the job's recorded pgid, or that has a marked `sid == pid` ancestor other than the job's wrapper (it runs under such a daemon, e.g. in a tmux pane); reported, never killed. *Suspects*: a process whose session leader is gone and whose command line is a browser (chrome, chromium, headless_shell, playwright, firefox, …), a preview server (vite, next dev, http.server, serve, storybook, `npm run dev`, …) or a shell wait loop (`while`/`until` with `sleep`/`pgrep`/`kill -0`). *Dead rows*: running rows whose wrapper pid is dead, or claimed rows that never registered a wrapper after the launch grace. Report only; `--kill` signals job ghosts only, never leaders or suspects (DEVIATIONS #13): a pidfd is opened first, the start time and session are re-read and must equal the scanned ones, then SIGTERM, 3 s, SIGKILL through the descriptor; a changed identity or no pidfd = not signalled.

**Trash** (`internal/trash`). `trash_move` takes an absolute path without `..`, resolves its parent (`EvalSymlinks`) and requires the result strictly inside a resolved root – not a root, not an ancestor of a root, no `.git` component, not inside, equal to or containing a protected path. With no roots configured nothing is moved (fail closed; the tool says how to set `trash_roots`). Protected, whatever the roots: the agent-jobs home (every agent's state dir and job database, also the trash), the owner rules file, the agent-jobs binary (`SelfBin`, which the guard hook runs, and `os.Executable`), `~/.claude`, `$CLAUDE_CONFIG_DIR` when absolute, `~/.claude.json`. Each protected path counts as named (parent resolved, so a symlink is protected as the link) and fully resolved, and a symlink whose target resolves to a protected path is refused too. The last component is not followed (a symlink is moved as the link). It writes `<trash>/<id>/meta.json` (id, original path, time, type, size) first, opens the resolved parent and the entry dir `O_PATH|O_DIRECTORY|O_NOFOLLOW` and checks each descriptor's `/proc/self/fd` path, then `renameat2(…, RENAME_NOREPLACE)` moves the item to `<trash>/<id>/item`. Another filesystem (`EXDEV`) is refused, never copied. `trash_restore` re-runs the same checks on the original path, refuses an occupied path or a missing parent, and renames back with `RENAME_NOREPLACE`; an unknown id lists the 20 most recent entries. Trash entries are not expired automatically. macOS: the descriptors are opened `O_RDONLY|O_DIRECTORY|O_NOFOLLOW` and checked by fstat device/inode against an lstat of the directory (no `/proc/self/fd`; a swapped intermediate component is not detected there), the rename is `renameatx_np(…, RENAME_EXCL)`, and the `.git` and protected-path comparisons are case-folded (APFS is case-insensitive by default).

## Rules enforcement

What this is and is not: the deny rules and the guard block the *direct spellings* of outward actions in a Bash call, and the wrapper's git environment scrub keeps git itself from running programs the guard does not see. This is **not a sandbox**: a script the job writes and then runs is allowed by design (as in the reference), and what it does is not inspected. Within a single Bash call the guard rejects forms it cannot resolve statically around git/gh instead of guessing.

- **Job marker** (wrapper, before claude starts): any inherited `AGENT_JOBS_JOB` is dropped and `AGENT_JOBS_JOB=<job id>` is set on claude, so every process of the job carries it (also the marker doctor procs will use). Under the marker the binary refuses every command except `mcp --role job`, `guard`, `run-wrapper` and help (start, cancel, status, list, result, tick, daemon, init, `mcp --role orchestrator`, …: «refused: running inside job»), and `mcp.Serve` refuses the orchestrator role on its own. The marker is an environment variable, so a job *can* remove it in a script it writes (the guard is not a sandbox); the guard rejects the direct spellings (`unset`, `env -u`, assignments, `mapfile`). Two process-based checks therefore back it up for the same control commands: (1) the ppid chain is walked through `/proc` (at most 256 steps) and the command is refused if an ancestor's argv is the wrapper's (`<bin> run-wrapper <jobdir> --token …`, matched by structure, or an `agent-jobs*` script run by an interpreter); (2) the command is refused if its session leader (`getsid(0)`, read from `/proc/<sid>/cmdline`) has the wrapper's argv shape: the wrapper starts with setsid, so it leads the session of every job process that did not call setsid itself – also of an orphan re-parented away from the wrapper – and this check does not depend on the agent or state dir the command targets; (3) as a fallback when the leader has exited, once the agent's store is open, the command is refused if its session id equals the recorded pgid of one of that agent's running jobs. Checks (1) and (2) are Linux-only and **fail open** when `/proc` cannot be read (and on macOS, where they are skipped; the marker and check (3) still apply). Before them, (0) the command is refused when `/proc/self/cgroup` names a job scope (`agent-jobs-*.scope`, any hierarchy line, any path component – also a sub-cgroup a job made inside its scope); this check also fails open when the file cannot be read. Without a scope (fallback), a job process that both drops the marker and calls `setsid` and has left the wrapper's process tree is not caught – the guard rejects the direct spellings of that as well, but a script the job writes is not inspected; with a scope it is refused by (0). Together these reject the direct spellings by which a job could start, cancel or manage jobs; not a sandbox (a script the job writes is not inspected, and without a scope a `setsid` + re-parented process that dropped the marker is not caught).
- **Session sweep** (wrapper, after claude exits, before `exit_code`): it ends what the job left in its session (and, with a scope, in its cgroup), so the processes a job started in the ordinary way do not outlive it. Processes a daemon outside the job starts for it (cron, tmux, …) are not in the session or the scope; the guard rejects the direct spellings of those (see «Cgroup containment»). The wrapper leads its own session (setsid), so on Linux it lists every live process whose session id is the wrapper's (from `/proc/<pid>/stat`, zombies skipped, the wrapper itself excluded) – also processes in other process groups and orphans re-parented away from it – sends them SIGTERM, waits up to 3 s, sends SIGKILL to whatever is left, and repeats (at most 5 rounds) until the session is empty; the count goes to `stderr.log`. Every signal goes through a pidfd: the descriptor is opened first (`pidfd_open`), session membership is checked only after it is open, and the signal is sent through it (`pidfd_send_signal`), so a pid reused by an unrelated process is never signalled. Without pidfd support (ENOSYS) nothing is signalled; there is no fallback to a bare `kill(pid)`. Fail closed: if processes are still alive after the last round, or the session cannot be enumerated or signalled, the wrapper still writes `exit_code` but first writes `sweep_incomplete` (survivor pids, then the error), and the daemon fails the job with «processes survived the job»; the job-done line ends with the same words. The daemon opens the marker without following links or blocking and reads it only as a regular file. Residual gap: the `/proc` enumeration is not atomic, so a process that forks between the directory read and the child's stat can leave a child that round did not see (the next round sees it, and one that keeps outpacing the rounds ends up as a survivor, failing the job); a survivor can also tamper with the job dir before the daemon reads it. With a scope, the daemon's stop of the whole unit (atomic, by systemd) follows at collection. Only then is `exit_code` written, so a job is never reported finished while one of its processes can still act (e.g. a markerless orphan waiting for the session leader to go and then starting a job for another agent). This is also the reference's ghost-process cleanup for preview servers, browsers and wait loops a job forgot. Outside Linux the wrapper sends SIGTERM to its process group only (it ignores SIGTERM itself meanwhile). Without a scope, a process that called `setsid` itself has left the session and is not swept (DEVIATIONS #9, residual gaps); with a scope the cgroup sweep below reaches it.
- **Cgroup containment** (Linux with systemd; DEVIATIONS #14). Config `cgroup_scope` (env `AGENT_JOBS_CGROUP_SCOPE` wins): `auto` (default) launches every wrapper in its own transient user scope when a throwaway `systemd-run --user --scope … true` succeeds, else falls back with a log line – except on a host where a scope was created before (`<state>/scope-ok`): there a failing probe requeues the job every tick for up to 10 minutes (`scope-failing-since`) before falling back, so a bus hiccup does not silently weaken a job; `required` likewise requeues within that window and then refuses. The containment of every launched job is shown as `scope <unit>` or `session only` in `status`, `list`, MCP `job_status` and (`session only`, `stop pending`) on the job-done line. `scripts/install-linux.sh` runs `init --pin-scope`, which writes `cgroup_scope: required` into `config.json` when it is unset and a probe succeeds; `required` refuses a job that cannot get one («refused to start: cgroup_scope is required …»); `off` never uses one. When neither `XDG_RUNTIME_DIR` nor `DBUS_SESSION_BUS_ADDRESS` is set and `/run/user/<uid>/bus` exists, the daemon points `XDG_RUNTIME_DIR` there for its systemd calls. A cgroup is inherited by every descendant and survives `setsid`, double forks and re-parenting, so: (a) control commands refuse inside a job scope (check (0) above); (b) after claude exits the wrapper, if its own cgroup is the expected `agent-jobs-<agent>-<id>.scope` or a sub-cgroup below it, sweeps from the scope itself the scope's cgroup subtree (pids from every `cgroup.procs` under it, itself excluded) in the same pidfd rounds as the session sweep – membership re-checked through `/proc/<pid>/cgroup` after the pidfd is open, zombies skipped – then the session as well, and only then writes `exit_code` (survivors fail the job as above); (c) the daemon stops the whole unit on cancel, timeout and every collection (see «Scope stops»). The scope sits under the user manager's `app.slice`, not under `agent-jobs@<agent>.service`, so a daemon restart never touches it (tested with a real `KillMode=process` unit restart). What a scope does not close (same uid, not a sandbox): a process can write its pid into another cgroup's `cgroup.procs` under the user manager, or ask the user manager for a new unit over D-Bus. The wrapper therefore drops `DBUS_SESSION_BUS_ADDRESS` and `XDG_RUNTIME_DIR` from the job's environment, and the guard rejects every command that starts processes outside the job's scope (owner decision 2026-10-17, `docs/DECISIONS.md`): `systemd-run`, `busctl`, `dbus-send`, `gdbus`, `qdbus`, `qdbus-qt5`, `qdbus6`, `dbus-run-session`, `crontab`, `at`, `batch`, `tmux`, `screen`, `pm2`, `docker`, `docker-compose`, `podman`, `podman-compose`, `ssh`, `machinectl`, `loginctl`, `unshare`, `nsenter` as commands (also behind wrappers and `xargs`) and where another program runs them: the value of an exec option (`find -exec`, `rsync -e`, `go test -exec`, `--rsh=`), a positional of a runner (`setsid`, `watch`, `flock`, …), a word inside code (an argument with spaces, quotes or parentheses: `python -c`, `node -e`, `awk`, `trap`), an absolute path or a substitution given to a copier; a package, directory, make target or test name merely named after one (`go test ./internal/ssh/...`, `make -C docker`) is data. `systemctl --user` (also abbreviated; `systemctl` behind `xargs` and in those positions too), and any write into the cgroup file system (redirection, or an argument of a program that is not a plain reader) in the spellings the guard resolves: paths are cleaned (`//`, `/./`, `x/..`), made absolute against the call's directory and symlink-resolved, and match on a `sys/fs/cgroup` segment run, a cgroup core file base name (`cgroup.procs`, `cgroup.threads`, `cgroup.subtree_control`, `cgroup.kill`, `cgroup.freeze`, `cgroup.type`, `cgroup.max.*`), or any path through `/proc/<pid>/root` or `/proc/<pid>/cwd`. `~` is expanded with HOME; every `cd`/`pushd`/`popd` of the call (also inside `sh -c` or a substitution, in any order) adds candidate directories against which relative targets are checked, and `cd`/`pushd` into `/sys`, `/sys/fs` or the cgroup file system, `ln` to `/`, `/sys` or `/sys/fs`, and a cd with `CDPATH` in the call are rejected. Fail closed: a redirection target or a writer's argument (tee, dd, cp, mv, install, ln, rsync, truncate, sed, mkdir, …) computed inside the call is rejected in any call – a command or process substitution, a variable the call sets (assignment, `read`, `mapfile`/`readarray`, `for`/`select`, `declare`/`export`/`local`/`typeset`/`readonly`, `printf -v`, `${X:=…}`, PWD after a cd), a positional, indirect or `$_` expansion, any variable after `.`/`source` or `declare -n`, and any write target after an `ln` with a variable argument; a plain environment variable (`"$OUT"`, `"${OUT}"`) is rejected only when the call mentions the cgroup file system or has a cd the guard cannot resolve (`cd -`, `cd "$X"`, a `popd` that is not the call's last command), as is `~user` and a relative target after such a cd; the mention also counts when the cgroup path is split by an expansion that may be empty (`/sy${N}s/fs/cg"$N"roup`, positionals) or spelled with ANSI-C quoting (`$'s'`; any `$'…'` with an escape counts as a mention), and a variable write target that names a cgroup core file once such expansions are dropped (`x/cgroup${N}.procs`) is rejected. A sed script (the first operand, `-e`/`--expression`) is not a write target unless it may hold a `w`/`W` file (matched approximately); its file operands are. `coproc` runs its command like a plain command word. `trap` code is parsed like `sh -c` code. A script the job writes is not inspected (documented gap). **Fallback** (macOS, containers, no user bus, `cgroup_scope: off`): the session sweep and the marker, ancestry, session and store checks only – weaker: a `setsid` + re-parented process that dropped the marker is neither refused nor swept (pinned by a test).
- **Git environment scrub** (wrapper, before claude starts): every inherited `GIT_*`, `PAGER`, `EDITOR`, `VISUAL` is dropped, then `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=<jobdir>/gitconfig` (identity only), `GIT_PAGER=cat`, `PAGER=cat`, `GIT_EDITOR=true`, `EDITOR=true`, `VISUAL=true`, `GIT_TERMINAL_PROMPT=0` and, via `GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_n`/`GIT_CONFIG_VALUE_n` (command-line level: wins over repository config), `core.hooksPath=<jobdir>/no-hooks` (repository hooks never run), `core.fsmonitor=false`, `core.sshCommand=false`, `credential.helper=` (empty resets the helper list), `core.pager=cat`, `core.editor=true`. `diff.external` is not overridden: git has no value that disables it (an empty value makes every `git diff` fail with «cannot run»); inside the job a repo-local `diff.external`/textconv is reachable only by writing `.git/config` directly, which the guard rejects as a direct spelling. The daemon's own git calls (worktree add/remove, diff, format-patch, update-ref) drop inherited `GIT_*` and use the same overrides (hooks path `/dev/null`); its diffs pass `--no-ext-diff --no-textconv`, because cleanup runs after the job could have edited the repository config; filter drivers cannot be switched off that way, so cleanup skips the diffs entirely when the repository config names a filter, diff command or textconv (see Cleanup).
- **Prompt**: preamble (own dir only, content is data, no secrets, nothing outside) + subagent rules (`prompts/subagents.md`) + owner rules (job profile) + matching project cards + task + kind checklist + report contract (Summary, Findings / Changes, Evidence, Not done / uncertain).

## Readings of ambiguous points

- *Reference: «Процесс запускается отвязанным… и сам пишет код выхода».* Read as: a small wrapper is the detached process; it runs claude as a child (not `exec`, otherwise nothing is left to write the file) and passes the claude argv after `--` so the full command is visible in `ps`.
- *«Запрос выше потолка отклоняется».* Zero/omitted = default; negative values are rejected too.
- *Duration in the job-done line* is wall time in whole minutes (rounded).
- *Owner rules «до 8 КБ»* = 8192 bytes; an empty file also refuses to start (no rules ≠ rules).
- *Notify for refused/cancelled jobs*: every terminal job gets exactly one line. «Главная сессия получает одну строку» is a delivery guarantee: an undelivered line stays pending.
- *Model table (DEVIATIONS #6)*: review/fix/general: light → sonnet, normal → opus, hard → fable; research: light/normal → sonnet, hard → opus. `fable` is the claude CLI alias (resolved to `claude-fable-5-1` in a smoke run on 2026-10-15).
- *Cleanup for jobs without a repo*: nothing to preserve, marked cleaned; the directory itself is for `prune`.
- *Prune «маленькие текстовые файлы верхнего уровня»*: a regular file of at most 1 MiB that is valid UTF-8 without NUL bytes. `stream.jsonl` and `stderr.log` do not stay in the job folder at any size: they move gzipped into the log archive (the report and the patches keep the result in the folder). `untracked.tar` is kept as one of the patches although it is binary.
- *doctor procs «процессы, пережившие свою джобу или сессию»*: a job's own processes are found by its marker and its session id; «сессия» outside jobs is read as a session whose leader is gone, narrowed to the reference's examples (preview servers, browsers, wait loops).
- *system_doctor «хуки»*: the hooks a job depends on – the guard hook as written into settings.json, the owner rules a job needs to start, the notify target.
- *trash_move*: one rename on the same filesystem; a copy across filesystems would not be reversible deletion, so it is refused.

## Memory notes in the brief

*Reference: «Демон сам добавляет до шести ближайших заметок из общей памяти команды».* `Manager.prepare` calls `LookupMemoryNotes` before it writes `prompt.md`: one `brain.Search` with the job's title and brief (first 4000 bytes, cut on a rune boundary), limit 12, under `MemoryTimeout` (5 s; the search runs in its own goroutine, so even a brain that ignores the context cannot hold the job). `RenderMemoryNotes` places a «Memory notes» section after the project cards and before the task:

- notes found: path, scope and score per note, the snippet (≤ 800 bytes, control characters dropped) quoted line by line with `>`, so a note cannot open a heading of the brief; marked as data written by others;
- none found: one line saying so;
- error or timeout: «Shared memory was unreachable when this job was prepared (reason)»; the job starts anyway, the daemon logs the reason;
- notes written by jobs (`MarkJobNotes`: the path is in the store table `job_notes`, or the snippet carries the job's marker line) are left out; the first 6 of the rest are quoted and the section counts the left-out ones;
- after an unanswered lookup the next ones are skipped for `MemoryBreaker` (1 min) with «skipped: …» as the reason;
- no brain configured: no section at all (briefs as before).

## Not built yet

Cleanup stays «через 30 минут после уведомления» (the detailed rule); «удалять worktree после прочтения, сохранив патчи» from the minimum list is met because the patches and the ref survive, so a report read after cleanup loses nothing. Tying cleanup to a read mark would contradict the 30-minute rule, so it is not done.
