# agent-jobs v0.6.0 (2026-10-26)

Milestones, codex jobs that write code, a merge gate that lets go once a release shipped, and lighter Wave F gates. The full list of changes is in [CHANGELOG.md](../../CHANGELOG.md).

## What changed

- **Milestones.** A large project is split into milestones (stages of work), a milestone into tasks with `depends_on`, and each task is worked on by jobs. One `milestone_create` call with a title and the tasks, then `job_start` with `milestone` and `task` per ready task: a blocked task is refused, `max_parallel` caps the running jobs, task status is derived from the jobs, and a task's job gets the accepted results of the tasks it depends on. Skills can be planned once per task (G01). `milestone_get`, `GET /v1/milestones/{id}` and `agent-jobs milestone <id> --json` return the full tree; the lists (`milestone_list`, `GET /v1/milestones`, `agent-jobs milestones`) return summaries unless asked for trees with `milestone_list(tree: true)`, `GET /v1/milestones?tree=1` or `agent-jobs milestones --json --tree`. Without `--json` the CLI prints text and tables. Sources (G02) are built but switched off until OS-level isolation lands.
- **Codex jobs can write code.** With `codex_write_allowed: true`, codex `fix` / `general` jobs write in their worktree and the wrapper commits once after the run, with the job's identity and within limits (2000 paths, 20 MiB per file, 200 MiB in all, a nested-repository scan of at most 200000 entries, one 2-minute deadline). Under codex's `workspace-write` sandbox network stays off unless `codex_write_network: true`; under `codex_sandbox: worktree-full-access` there is no codex sandbox, so the job has network whatever `codex_write_network` says and commits itself (no wrapper commit). New `codex_sandbox` (`auto` | `native` | `worktree-full-access`) for hosts where codex's bwrap cannot start; a codex job whose sandbox did not start now ends `failed`.
- **The merge gate stops gating a shipped release.** When `release_check` passed at the latest approval on a sha that is on origin's default branch (by ancestry, or the same tree for a squash merge), the daemon marks the approval shipped and later fix PRs merge without a new judge, until the next approval.
- **Wave F gates cut back.** The judge may be of the coders' model family (it is a separate blind job; the family is information), a Codex judge under the read-only sandbox counts as blind, `trace` is gone, waivers survive fix commits, an unreadable merge command runs with a warning, requirement lines count as written, size and slicing are optional.
- **Guard.** File and package operands of `go`, `gofmt`, `sed`, `diff` and `cmp` are data (fewer false blocks); a `sed` script with a bracket expression fails closed, `go install` and Go env assignments are scanned.

## Upgrade notes

Rebuild and install the binary (README «Build and check»), then start a new session so that Claude Code reports MCP server 0.6.0. The store adds its new tables and columns at the first `Open`.

1. **Run `release_check` again after upgrading.** A pass stored before v0.6.0 is not bound to an approval and never ships one, so a gated repository stays gated until `release_check` passes again on the released sha.
2. **Do not roll back across this release.** A binary from before it rebuilds the waivers table to the old key (without the checklist id) and can merge the waivers of two checklists with the same hash, version, sha and requirement into one.
3. Codex write jobs need `codex_write_allowed: true` (and `codex_write_network: true` for package installs); both need a daemon restart to turn on.

## Known issues

- **The shipped check's git calls have no timeout** ([#100](https://github.com/qwwiwi/agent-jobs/issues/100)): a hung git (lock, NFS, credential prompt) stalls the daemon's whole tick.
- **Flaky tests under load:** `TestStopRunningThenResumeSameSession` ([#101](https://github.com/qwwiwi/agent-jobs/issues/101)) and `TestProtectedLargeInlineScriptFast` ([#102](https://github.com/qwwiwi/agent-jobs/issues/102)) can fail in a full `scripts/check.sh` run on a busy host and pass on rerun.
- **An older pass can overwrite a newer one for the same sha** ([#103](https://github.com/qwwiwi/agent-jobs/issues/103)): a slow `release_check` that read the previous approval leaves the repository gated until `release_check` runs again. It fails closed.
