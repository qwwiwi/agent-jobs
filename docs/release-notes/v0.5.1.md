# agent-jobs v0.5.1 (2026-10-25)

A fix release for the merge-gate hook of v0.5.0. The full list of changes is in [CHANGELOG.md](../../CHANGELOG.md).

## What changed

- **Fewer false blocks while a repository is gated.** The merge-gate reader no longer refuses:
  - the word `merge` as a data argument of a `gh pr` call (`gh pr create --title merge`, `gh pr list --label merge`, `gh pr view merge`);
  - a quoted heredoc PR or commit body with extglob-like text such as `**(` or `C++(` (`-m "$(cat <<'EOF' … EOF)"`);
  - a separate quoted `-R "$R"` before the subcommand (`gh -R "$R" pr view 5`).
- **Complex shell syntax is still read strictly, as in 0.5.0.** A command with `${…}`, `$[`, `$'…'`, `((`, `[[`, a backtick, process substitution, an unquoted `#`, `eval`, `source`, `case`, `xargs`, `sudo`, `doas`, `su`, `runuser`, an attached `-R"$R"` and similar forms gets no relaxed reading: it keeps the strict 0.5.0 behaviour, known gaps included (a root shell mode such as `sudo -s gh pr '$M' 5` hides a merge from it; see the Risks list of [PLAN.md Wave F](../PLAN.md#wave-f-brief-acceptance-gate-released-in-050)), and a harmless call that 0.5.0 refused is still refused.

## Upgrade notes

Rebuild and install the binary (README «Build and check»), then start a new session so that Claude Code reports MCP server 0.5.1. No config, store or hook registration changes.

## Known issues

- **The merge-gate reader still refuses some harmless commands while a repository is gated:** a comment with extglob-like text, a command with a `${...}` form, and a Codex prompt that mentions the word `merge`. Workaround: pass the body with `--body-file`, and the prompt from a file.
- **A Codex judge cannot see the job files.** Unchanged since 0.5.0: see the [v0.5.0 notes](v0.5.0.md).
