### (a) CHECKLIST

| ID | Requirement | Acceptance |
|---|---|---|
| G01 | Gate lock per repository, plus a box semaphore of N slots (`gate_max_parallel`, default 2) | Gates in two different repos run at once; two in the same repo serialize; a third waits when N=2 |
| G02 | Gate timeout configurable (`gate_timeout_minutes`, per-card `gate_timeout:`), default 60 min | A job's `gate run` without `--timeout` uses the configured value; explicit `--timeout` still wins |
| G03 | Old and new binaries never run gates together during the upgrade | The new gate takes a shared flock on the legacy lock file; a test with a legacy exclusive holder blocks it |
| G04 | Fix-loop cap in the daemon (`review_max_fix_loops`, default 2) | A third `job_start(kind fix, review=…)` on one chain is refused, naming the chain |
| G05 | Cap bypass only with `design=<succeeded research/general job id>` or `loop_override="<reason>"` | Either is accepted, stored on the job and shown in the job-done line and `job_status` |
| G06 | Stop rule in the control review | Brief and `kind-review.md` say: a finding is closed when its original scenario no longer reproduces; a deeper scenario is Non-blocking unless it shows reproducible money or data loss with steps |
| G07 | Provider docs for claude fix/general/review jobs: WebFetch allowed only to hosts in `web_allow_hosts`; WebSearch stays closed | Guard allows an allowlisted https host and refuses any other host, IP literals, userinfo and non-https; empty list behaves as today |
| G08 | Provider docs for codex jobs: `docs: [url]` on `job_start`, fetched by the daemon into `sources/` | Allowlisted URL lands as a text file within the 2 MiB cap; redirect off the allowlist is refused; the prompt marks it as data |
| G09 | Gate result artifact for reviewers | Acceptance result (trusted) and the job's gate runs (job-reported: head, argv, exit, duration, 16 KiB tail) are written to `gate-results.json` and attached to the control review |
| G10 | Review prompt uses the artifact | "Tests could not be run" is not a finding when the artifact shows exit 0 at the reviewed HEAD; a missing or red artifact is reported |
| G11 | Prepare step documented for codex reviewers (venv through `prepare`, #120) | GUIDE recipe plus a test that a codex review job with a matching entry gets `--prepare` |
| G12 | Event-driven start | Daemon ticks on SIGUSR1 from the wrapper (after its result is stored) and from Enqueue; a queued job starts under 3 s after a slot frees; the minute tick remains |
| G13 | Kicks are debounced | A burst of 20 kicks causes at most 2 ticks (1 s debounce) |
| G14 | Card `review_questions:` (race, retry, dependency, rollback, residual-risk) | The matching questions appear in fix/general prompts and must be answered in the report; an unknown value fails `ParseCard` |
| G15 | Card `ui: true` makes the screenshot matrix part of acceptance | The prompt states it as acceptance; a succeeded job with a UI diff and no `ui-check/` evidence gets a note on its job-done line |
| G16 | Docs and changelog | GUIDE, REFERENCE, `orchestrator.md` and the skill updated; one fragment per issue; `scripts/check.sh` green |

### (c) Release and install
1. After the slices merge, in a release worktree run `go run ./cmd/changelog --check`, then `go run ./cmd/changelog`, and move the entries under `## [0.8.2] - <date>`.
2. Run `PR_TITLE='Release v0.8.2' scripts/check.sh` and `scripts/acceptance-clean-clone.sh --from . HEAD`.
3. Open the PR, squash-merge, tag `v0.8.2` (orchestrator only).
4. Install on Thrall from the tagged checkout with `scripts/install-linux.sh --instance thrall`. The script's restart comment (`:347`) says `KillMode=process` keeps running jobs alive; the daemon logs the same on stop (`main.go:1521`).
5. Before the restart, wait until `agent-jobs status` shows no job waiting for the gate lock. G03 is the safety net if one is.
6. After the restart, check that `agent-jobs version` and `daemon.json` show v0.8.2, restart the orchestrator session's MCP server, and run `system_doctor`.
7. Edit `config.json` only after that: `web_allow_hosts`, `gate_timeout_minutes: 60`, `gate_max_parallel: 2`. New keys in an old daemon may be rejected. Every `web_allow_hosts` entry is an outbound channel (a job chooses the path and query of each request), so list only vendor-owned docs hosts without user content.
8. Smoke test: two gates in two repos overlap, and a queued job starts within seconds of another ending.
9. Roll back by reinstalling v0.8.0 with `--binary`; new store columns are additive.

### (d) Risks
- **Memory.** Two full suites at once inside the 12G slice. N is configurable; start at 2 and watch for OOM.
- **Missed edge case.** The stop rule can let a real defect through. The money/data-loss exception and the logged override limit this.
- **Cap bypass.** An orchestrator can start a fix without `review=`. The daemon cannot see that; only `orchestrator.md` covers it.
- **Prompt injection through docs.** An allowlisted page can still carry instructions. Mitigations: https only, exact hosts, WebSearch closed, content labelled as data, review jobs stay read-only.
- **Mixed versions.** Wrappers already running keep old code while their `gate run` calls use the new binary. G03 covers the lock; a v0.8.0 wrapper sends no kick, so the minute tick must stay.
- **Biggest win is outside this release.** The edgelab-space suite is red on base and takes about 50 minutes (audit c1). Without fixing it, G01 and G02 only remove the queueing, not the runtime.
