- Job-done lines can reach an orchestrator that does not live in a tmux pane: config `notify.command` runs a program (an argv, no shell) with the line on its stdin (10 s timeout, a failure is logged and never fails the job), and `notify.inbox_dir` stores each line as one JSON file (`id`, `line`, `ts`, mode 600) that the new `agent-jobs inbox pull --agent A [--ack]` prints and acknowledges from a session hook (pulls take turns, a line is removed only after it was written, and an inbox dir others can write is refused). Both are off by default, follow `notify_coalesce_seconds`, and work with or without `notify_tmux_target`; they run outside the lifecycle lock, two lines at a time, at most once per batch, and without a tmux target an owner-waits job counts as delivered only when they all took its line; `examples/notify/loopback-webhook.sh` posts the line to a loopback webhook with a token read from a file (#9999).
